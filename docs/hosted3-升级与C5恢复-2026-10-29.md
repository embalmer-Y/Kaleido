## 2. C5 卡死战报（时间序）

1. **3.x host × 2.x slave 硬阻断（实证）**：3.x connect 时双检查
   无条件致命——芯片枚举（C5=0x0d，旧 slave 上报 0x17=旧编号）+
   主版本。迁移文档兼容表与实现不一致（"back-compatible"不成立）。
2. **官方路径执行**：按迁移文档"host OTA 升 CP"——构建 3.0.10
   C5 slave（esp-hosted-mcu v3.0.10 源码，examples/wifi/sta/cp，
   registry 组件），临时桥接固件（2.12.9+defer-init 补丁+'Z' 键
   OTA 例程，emote_gen 分区暂存镜像）——**OTA 传输全量成功**
   （1,147,968B，PROG 全程，end+activate OK，C5 重启）。
3. **activate 后 C5 无应答**：3.x host bring-up 5s 超时；2.x 桥接
   回探同样失败——`sdio_card_fn_init failed`+CMD53 超时（0x107），
   **C5 在 SDIO CMD 层完全无应答=新镜像早期启动挂死/崩溃循环**。
4. **根因嫌疑（按概率排序）**：
   ① 镜像用 IDF v6.1 构建，官方 CI 是 **v5.5.4**（.gitlab-ci.yml
   IDF_VER）；C5 出厂 bootloader 为 2.12.x 时代（5.x）——跨大版本
   app×boot 兼容性无保证；
   ② 我方 4KB 分块 OTA 写若有尺寸约束不符（官方示例分块未核对），
   镜像可能损坏——但 2.x slave 端 end() 有校验且通过，概率低；
   ③ 新镜像 CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=n——崩溃无
   自动回退（若出厂 bootloader 带回退且镜像为崩溃循环，理论上应
   已回退——未回退，故更像**挂死而非崩溃**）。
5. **根因已定位（上游 issue 证据链闭环，10-29 晚）**：
   **esp-idf#18886**——IDF 6.0.2/6.1-rc1 的 ESP32-C5 app 因 RISC-V
   ZCMP 回归在进 app_main 前即崩（Interrupt WDT，"never gets to
   app main"），修复 commit 104f8ff5 仅在 master 未进 release/v6.1
   （报告者 8-19 确认 6.1-rc1 仍在）。我方镜像=v6.1 构建→崩→SDIO
   从机永不初始化。排除项：C5 bootloader 文档明确 5.x bootloader
   可启动 6.x app（版本门不成立）；5.5.4 自带 SOC_CPU_ZCMP_
   WORKAROUND（该区域 6.x 才回归）。过程副发现：esp-hosted-mcu#128
   （P4 经 RPC OTA 更新 C5 的已知抖动，同栈组合）。
6. 已备：IDF v5.5.4 环境 + v5.5.4 构建的 cp 全套镜像
   （tools/hil/c5-recovery/，含今晚物理烧写执行单）。

## 3. C5 恢复预案（按代价排序）

**A. 断电试验（零成本，负责人可立即做）**：整机断电 10s 再上电。
消除"SDIO 控制器/电源域瞬时楔死"假设。C5 flash 的 boot 目标已是
新镜像，断电大概率无效，但 2 分钟排除一类原因。若复活（回到应答
态=2.x 或 3.x），立即用桥接 'Z' 重 OTA v5.5.4 镜像。

**B. C5 物理烧写（确定路径，已备齐）**：**负责人确认板上有物理
切换开关**（晚上回家切换）。执行单与全套镜像在
tools/hil/c5-recovery/README.md（v5.5.4 构建；先整片备份再刷；
2MB flash 兜底方案已注明）。

**C. osptek 求援**：出厂预烧方应有 slave 重烧程序/夹具说明；同时
可问出厂镜像是否含恢复机制（如 bootloader 回退使能）。

**D. 上游询问**：host 3.x 拒连 2.x CP 与迁移文档矛盾——已具备
完整证据包（芯片枚举编号变更+双检查源码位置），可在 esp-hosted-mcu
提 issue 请官方确认 C5 的 2.x→3.x host-OTA 路径是否实际可用
（怀疑 C5 芯片枚举改号是迁移遗漏）。

## 5. 教训

- **跨大版本 IDF 产物不混烧**：C5 镜像必须与官方 CI 同版 IDF
  （v5.5.4）构建——首次就该对齐，而不是事后补救。
- OTA 前先核对官方示例的分块参数与回退配置
  （BOOTLOADER_APP_ROLLBACK 应开启再 OTA，给自己留后路）。
- 迁移文档的兼容表要拿实现源码验证（本次"back-compatible"
  三行代码就证伪了）。
- 无 WiFi 降级模式是产品必修课（本次顺手落地）。
