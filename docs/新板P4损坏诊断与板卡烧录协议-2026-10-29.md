# 新板 P4 损坏诊断与板卡烧录协议（2026-10-29 结案）

## 结论

新板（第二批 ESP32-P4C5 模组板）**P4 芯片本体死亡**，其余子系统全部健在。
判定依据链：

1. 到货时 P4 存活：esptool 读取到 P4 ROM 横幅（boot mode 0x307），UART 通路完好；
2. AMOLED 上电冲击 → 3.3V 轨塌陷 → 20 秒 375 次 POWERON 复位循环；随后双 USB 并
   供电发生地环路对轰（严重啸叫）——P4 死亡窗口与此完全重合；
3. 之后 P4 侧全哑：电气复位（esptool 全部 before 模式）、RTS 脉冲、双极性
   DTR/RTS 舞蹈、物理 RST/BOOT+RST 均无任何 ROM 横幅；
4. **同一时段 C5 侧完全正常**：手动 BOOT+RST 进下载 → no-reset 同步成功
   （MAC 7c:0c:5f:01:e2:68），证明 CH343、RS2233 公共腿、电源轨、按键全好；
5. 数据口 Type-C（直通 P4 的 USB-Serial-JTAG，不经过 RS2233）插线后零枚举
   （TS3USB221 的 VIN2_5V 自动选通已核实），P4 的 USJ 也是死的 → 芯片本体死亡。

**保留价值**：本板 C5 侧完好（v661 镜像已烧），可作 esp-hosted/WiFi 验证备板。

## 电路事实存档（原理图第 6 页 + 局部放大，此后所有板卡操作通用）

| 网络/器件 | 事实 |
|---|---|
| P4 UART0 | **GPIO37 (TX) / GPIO38 (RX)** |
| RS2233 (U10) | 只切 UART：公共腿=CH343 DBG_RXD/TXD，两侧=C6_U0TXD/RXD 与 P4 GPIO37/38；选通脚由拨动开关 S1（R23 10K 上拉）控制 |
| BOOT 网 | **两芯片共用**：U7 双三极管 DTR→BOOT（与 BOOT 键 K2 并联，R35 10K 上拉）；C5 侧经 R56 0R 到 GPIO9，P4 侧接 GPIO35 |
| ESP_RST | RTS→三极管（与 RST 键 K1 并联，R1 10K 上拉） |
| TS3USB221 (U15) | P4 USB_D_P/N 在数据口 Type-C 与 USB-A 之间切换；S 端 R42 10K 默认上拉（USB-A），**数据口 VBUS 经 Q1 自动切到 Type-C**——只插一根线即可 |
| 30P 显示座 | YDP400BT001-V4：DSI_D1/CLK/D0 差分对 + 触摸 I2C（GPIO7/8）+ TP_RST GPIO6 + 3V3。**无 QSPI 屏引脚** → QSPI 版屏幕在本板点不亮是设计使然 |
| CSI 15P (J5) | RPi 兼容：CSI_D0/D1/CLK + CSI_RST GPIO10 + I2C GPIO7/8 |
| CH343 自动复位 | 本板系 esptool 电气自动复位**从未成功**（两块板一致）——原因待查（疑似 CH343 DTR/RTS 极性），不影响生产：手动按键协议可靠 |

## 板卡烧录协议（SOP）

```bash
# 1. 拨动开关切到目标芯片位（上=P4，下=C5）
# 2. 手动进下载：按住 BOOT → 按 RST → 保持 BOOT 约 2 秒 → 松开
#    （ROM 下载模式无限期等待，不赶时间）
# 3. 从 build 目录一次性烧全部镜像（@flash_args 在 build/ 下，
#    idf.py flash 的相对路径解析有 bug，直接调 esptool 更可靠）：
cd <project>/build && esptool --chip esp32p4 -p /dev/ttyACM0 \
    --no-stub --before no-reset --after hard-reset write-flash @flash_args
#    P4 必须 --no-stub（stub 坏）；esptool 用 idf6.1 环境：
#    ~/.espressif/python_env/idf6.1_py3.14_env/bin/python -m esptool
# 4. 跨 esptool 调用会话会丢：每个操作前重新 BOOT+RST
```

**【修订 10-30】手动 BOOT+RST 只是新板（电气自动复位损坏）的特例——
正常板（旧板两颗芯片均实证）esptool 电气自动复位直接可用**：
`--before default-reset` 一步进下载，无需任何手动操作。自动复位偶发
`Packet content transfer stopped`（USB 层抖动）重试即可。SOP 判定：
先 default-reset 探测，失败才降级手动 BOOT+RST。

## 新板防损守则（屏幕冲击是本次死因，必须遵守）

0. **FPC 排线方向是第一嫌疑**（2026-10-29 晚复盘定案）：排线反插=电源脚对地短路，
   症状为 17~19Hz 纯 POWERON 复位循环 + 板载 NS4150 功放把电源振荡啸叫放大。
   新板 P4 的死亡窗口与反插排线的连接窗口完全重合，"AMOLED 浪涌"实为反插短路
   冲击；旧板当晚以 17Hz 同签名循环复现，纠正排线方向后立即恢复正常启动。
   **接排线前后各看一眼金手指方向/丝印，接完先看 LED 与串口再继续。**
1. **先烧后插屏**：到手先完成烧录验证，屏幕最后接；
2. **插屏必断电**：接/拔屏幕 FPC 前拔掉 USB；
3. **永远单电源**：数据口有自动切换，第二根线只有害处（地环路对轰）；
4. 首次点亮亮度 5%（panel-2in 已按此构建，`esp_lcd_panel_co5300_set_brightness(s_panel, 5)`）；
5. 上电后 10 秒内若出现 POWERON 复位循环（Guru → 瞬间复位），**立即断电**——
   优先检查排线方向，其次才是电源轨。
