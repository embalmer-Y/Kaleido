## §2 persona 包格式设计

### 2.1 设计原则

- **角色 = 大脑的外壳参数集**（架构 P4/§3.1）：persona 包不含可执行代码，是**纯声明式数据包**（JSON + 资产）。这从根本上区别于 KApp（含 Lua 入口）→ 安全校面小一个量级（无代码执行 = 无需权限位图与崩溃回滚机制）。
- **可手工编辑**：用户可用文本编辑器改 persona.json 的大部分字段（除资产索引外），社区分享友好。
- **资产与描述分离**：JSON 描述 ≤16KB（NAND 直读、解析快），大资产（EAF/PNG/Lottie JSON）按索引懒加载。

### 2.2 目录结构（运行时为解包目录，分发为 zip）

```text
NAND FatFS:
/personas/                          ← persona 根（DATA root，可写）
  com.kaleido.persona.momo/         ← 出厂角色（同时烧入只读 assets 分区时挂载为 SYSTEM 遮蔽，见 §2.4）
    persona.json                    ← manifest（唯一必需文件，≤16KB）
    LICENSE                         ← 资产许可文本（必填，开源纪律 §5.3）
    icon.png                        ← 128×128，角色选择列表用
    card/
      system_prompt.md              ← 人设主模板（长文本外置；persona.json 内可内联短版）
      interview.md                  ← 可选：访谈式创建时的问答存档（用户可见可删）
    assets/
      layers/                       ← L0 骨架分层（承 20 §6.1 基座 I）
        body.bin                    ← LVGL image bin（RGB565+A8，构建工具转换）
        eye_l_open.bin  eye_l_closed.bin
        eye_r_open.bin  eye_r_closed.bin
        brow.bin  front_hair.bin  acc.bin
      emo/                          ← L1 情绪 EAF（承 20 §6.1 主力 II）
        happy_loop.eaf  sad_loop.eaf  angry_loop.eaf  surprised_loop.eaf
        sleepy_loop.eaf  thinking_loop.eaf  relaxed_loop.eaf  confused_loop.eaf
      act/                          ← L3 一次性动作
        nod_once.eaf  cheer_once.eaf  sleep_in_once.eaf  wake_once.eaf
      viseme/                       ← L2 口型帧（骨架层的嘴部替换帧，5 帧）
        m0.bin .. m4.bin
      fx/                           ← 可选：Lottie 小窗（承 20 §6.1 点睛 III，一期可空）
        sparkle.json
```

**分发格式 `.kpersona`** = 上述目录的 zip 包（store/deflate 均可，签名不做——架构 P2"无鉴权链，仅来源标记"同款）。侧载时解包到 `/personas/<id>/`，`persona.json` 最后写入（防半成品包被识别，沿用 esp-claw app-package-spec 的发布纪律，A 级）。

### 2.4 与 KApp 机制的关系：**格式独立、基建复用**

| 维度 | KApp（架构 §2） | persona 包 | 裁决 |
|---|---|---|---|
| 内容 | 含可执行代码（Lua/C） | **纯数据**（JSON+资产） | 独立 schema |
| 安全模型 | 8 权限位图 + 崩溃回滚 | 无代码 → 无权限位图；仅需资产路径校验 | 不复用权限系统 |
| 并存语义 | 多 App 常驻、前台唯一 | **全局至多一个激活角色**（互斥） | 独立注册表 `kpersona` |
| UI 呈现 | 主屏 App 网格 | 设置内"角色"页（选择/管理/创建），不进网格 | 独立入口 |
| 安装通道 | 商店/Claw 生成/USB/WiFi | USB/WiFi 侧载 zip + 设备上直接创建；**扫描/解包/来源标记复用 KApp 文件扫描基建**（kapp 框架新增包类型钩子，改动 ≤200 行 C） | 复用基建 |
| SYSTEM/DATA 遮蔽 | 支持 | 支持：出厂角色可烧只读分区，用户改配色等"轻定制"落 DATA 遮蔽层（`overrides.json` 合并语义） | 复用思想 |

**裁决理由**：把 persona 塞进 KApp 框架需要给"无代码数据包"硬造权限语义和生命周期语义（App 的 RUNNING/PAUSED 对数据包无意义），且 App 网格心智错位（角色不是用户"打开"的东西，是设备"是谁"）；反过来，persona 又确实需要"从哪来、可信度标记、删了会不会砖"这些 KApp 已解决的问题——所以**分发层复用、模型层独立**。esp-claw 的 `apps/<id>/` 目录约定、DATA 遮蔽 SYSTEM、manifest 最后写入三条纪律原样继承（A 级）。

**内置出厂角色**：1 个（com.kaleido.persona.momo 或最终命名），烧入只读 assets 分区作为 SYSTEM persona；用户可创建/导入任意数量（NAND 空间限），同时仅一个激活。

## §3 角色创建 / 切换 UX 链路

### 3.1 三条创建路径（按优先级）

**路径 A：设备语音访谈式（主打，差异化卖点）**
1. 用户对设备说"我想捏一个新角色"（或设置页入口）→ Claw 进入**访谈模式**（一个专用 skill/prompt，非普通对话）；
2. LLM 按 5-8 个固定维度访谈：名字/性别感与年龄感/性格三词/说话风格示例（让用户"学它说一句话"）/喜好与雷区/和用户的关系设定；
3. 访谈结束 → LLM 单次调用产出：character_card 草稿（system_prompt + greeting + language_style）+ 情感参数建议（如"高 arousal 初值"）+ ignition 建议（JSON 严格输出，复用 22 §4.1 裁决调用形态）；
4. 设备端模板化落包：形象沿用**内置模板改色**（§5.2），音色默认 fallback 预置音色 → 得到完整可激活的 persona 包；
5. 用户在屏上预览（试听一句 greeting + 看形象）→ 确认保存或继续微调。
- 成本：~2 次云调用（访谈多轮 + 一次装配），BYOK 承担；离线时此路径不可用（引导走路径 B）。

**路径 B：网页配置（设备 HTTP server）**
- 设备配网页（WiFi provisioning 本就需要 HTTP server）扩展"角色工坊"页：表单全字段编辑（persona.json 可视化）+ system_prompt 在线编辑器 + greeting 试听（走设备 TTS）+ 访谈记录查看/删除。
- 定位：**能力最全的编辑器**（路径 A 的产物也在此精修）；同时承担音色复刻流程 UI（§3.2）与导入导出（.kpersona 上传下载）。

**路径 C：App 内表单**
- 二期再评估。一期不做独立手机 App（人力集中在固件），网页版已覆盖。列入开放问题 O-6。

### 3.2 音色复刻流程（承 19 §2.1 voice-enrollment）

```text
[网页/屏引导] 阅读同意声明（声音权益，19 R5）→ 朗读指定文本 15s（16kHz/16bit/mono wav，设备录音）
   → 设备直连百炼：POST create_voice（参考音频 base64 + target_model=cosyvoice-v3.5-plus + 前缀）
   → 轮询 query_voice 至 OK（UI 进度提示，通常秒级-分钟级）
   → 得 voice_id → 回填 persona.json：voice.{model, voice_id, enrollment.status="cloned"}
   → 试听一句 → 用户确认 → 包内激活
[失败/超时] 保留预置 fallback_voice_id，提示"音色克隆失败，已先用预置音色"
[自托管用户]（19 组合 C）：样本上传自托管 CosyVoice3 网关，回填 provider="selfhosted" + 网关侧 voice 句柄
```

- **key 归属**：复刻用用户自己的百炼 key（NVS，BYOK）；设备直连（不做手机代理中转）——与 LLM/ASR/TTS 同一把 key，链路最短。若负责人对 key 安全有更高要求可加"经配网页代理上传"选项（开放问题 O-5）。
- **样本留存**：默认本地 `sample_ref` 留档 + 用户可删；上传即接受百炼侧数据条款（声明文案内含）。
- 每账号 1000 音色上限（19 §2.1）→ 删除角色时提示"是否同时删除云端克隆音色"（调百炼 delete 接口）。

### 3.3 切换角色 = 激活另一个 persona 包

切换链路（目标 <2s 完成，无重启）：
1. 设置页/语音指令选择目标角色 → `kpersona_activate(id)`；
2. **动画**：旧角色播 300ms 淡出 → 卸载图层缓存（释放 1-1.5MB PSRAM）→ 新包 `exp_register_assets()` → 淡入 + wake 动作（act/wake_once.eaf）；
3. **语音**：TTS WS 任务下一请求即读新 voice_id（WS 长连接不重建，只换参数——CosyVoice 音色是 run-task 参数，19 §2.1 协议天然支持）；PCM 管线零变化；
4. **LLM**：下一轮 system prompt 用新 character_card 装配（prompt 组装器读当前激活角色）；
5. **情感**：加载该角色 affect 快照（§3.4）；**点火**：打分器换新角色 ignition 权重与配额（22 §4.1 的 w2/配额门参数来自激活包）。

### 3.4 记忆与情感的归属裁决

| 资产 | 裁决 | 理由 |
|---|---|---|
| episodic/raw 记忆（关于**用户**的经历） | **全局共享，跨角色**，每条记 `persona_id` 标签（21 §4.2 episode 条目加一字段） | 设备认识的是"主人"这个人：换角色不换主人。带标签使"每个角色只检索自己经历过的"成为可选过滤器（默认关闭） |
| core · 用户事实块（用户是谁/偏好） | **全局共享**（`user_facts_policy: "shared"`） | 同上；且这是 21 号 ChatGPT 式"用户可见可管理"边界，单一界面管理一份事实最清晰 |
| core · persona 块 | **每角色独立**，初值来自 `memory_init.core_persona_block` | 角色的自我认知属于角色（MemGPT 范式本来就把 persona/human 分块，21 §4.1） |
| 情感状态（九维快照 ~40B） | **每角色独立快照，激活时恢复**（NVS key = persona id；不做"重置"） | ① 切回常用角色时情感连续是"灵魂连续"卖点；② 成本仅 40B/角色；③ 若共享，上一角色残留的负面情绪会污染新角色第一印象。提供手动"重置心情"入口（设置内） |
| ethics_latched（18 §2.4 伦理闩锁） | **全局，不随切换清除** | 安全状态优先于角色连续性（负责任设计） |

## §4 kaleido_express 子系统设计

### 4.1 定位与数据流总览

`kaleido_express` = ESP-IDF 组件（components/kaleido_express/，纯 C，Linux 内核风格），**消费三方输入、驱动一个舞台**：

```text
输入① 云端 LLM（经 Claw agent loop）
        句级内联 [tag]（主）+ 整轮 {"emotion": tag}（兜底）+ 可选 action 字段
        —— 承 20 §4.2 协议，23 词表
输入② kaleido_emotion ke_output（1Hz）
        anim（valence×arousal → 角色 plane_map 查 tag+intensity）
        tts（rate/pitch/volume 基线偏移）—— 承 18 §4.2
输入③ kaleido_audio
        焦点事件（VOICE_CALL / TTS_ANNOUNCE 获取与丢失）+ 播放流 RMS 电平回调
                  │
                  ▼
        四层合成状态机（承 20 §4.2）
        L0 骨架常驻（呼吸/眨眼/小动作）  ← 无输入时自治运行
        L1 情绪循环（EAF 全屏）          ← ①②仲裁：LLM 显式 tag > ke 查表 > 保持
        L2 口型（viseme 换帧）           ← ③激活（RMS→帧索引，静音回落）
        L3 一次性动作                    ← ① action / 点火开场
        仲裁：SYS（低电/连接中）> SPEAK > EMOTION > IDLE
                  │
                  ▼
        KShell 舞台（LVGL 对象树）+ TTS hint 回写语音链路
```

**情感→动画双通道仲裁细则**（本文增量设计）：LLM 句级 tag 表达"这句话的情绪"（即时、语义），ke_output 表达"持续心情"（动力学、慢变）。规则：LLM tag 命中后 30s 内锁存该情绪层（ke 查表结果仅调 intensity 不换 tag）；锁存过期后回到 ke 心情主导；情绪切换频率限 0.5-1Hz 防抖（承 20 §4.2）。**ke TTS hint 与 LLM tag 不冲突**：hint 只调制语音参数不改文本。

### 4.2 裁决：esp_emote_expression 借架构自研（回答 20 号遗留 #7）

**不直接集成，理由（B 级证据 + 项目事实）**：
1. **双渲染栈冲突**：esp_emote_expression 依赖 esp_emote_gfx 自有渲染栈（非 LVGL），经 flush_cb 直推 panel；KShell 是 LVGL9 + PPA 主栈。直接集成 = 系统内并存两套 UI 运行时（两份任务、两份帧缓冲、显示通路互斥），PSRAM 与内部 RAM 双重浪费——与架构 P5/P6 冲突。
2. **UI 职权重叠**：其 label/qrcode/timer UI 对象体系与 KShell（状态栏/Toast/页面栈）大面积重叠，等于在 App 框架外再造半个 UI 层。
3. **资产管线绑定**：其 .bin+index.json 打包与 CMake 生成工具（esp_emote_assets）面向其自有格式；Kaleido 的资产要 per-persona 可安装（NAND 任意目录），管线必须自己走。

**借什么（架构参考价值，承 20 §3 EAF 条目）**：
- 事件模型语义：IDLE/SPEAK/LISTEN/SYS/SET/BAT/OFF 七类事件消息 → 映射为本设计四层仲裁的输入事件；
- 插播对话动画（anim dialog + 自动停 + 等待完成）：即本设计 L3 + `EXP_EVT_ACTION_DONE` 回调；
- 资产 .bin + index.json + mmap 思想：persona 包 assets 索引 + NAND mmap（esp_mmap_assets 已在 vendor，A 级）。

**EAF 播放器直接用**：`espressif__esp_lv_eaf_player`（Apache-2.0，LVGL widget，**已在 vendor esp-claw managed_components**，A 级本地核实：`lv_eaf_create/set_src/set_loop_count/pause/resume` API 齐备）——L1/L3 的播放内核零自研。

### 4.3 与 KShell / KApp 的关系：**UI 层原生舞台，非 App**

**裁决：角色形象由 KShell 提供"舞台容器"（stage），kaleido_express 组件在容器内建对象树；不注册为 KApp。**

理由：
1. KApp 生命周期语义不匹配：后台 App 会被 LRU 暂停（架构 §2.4），而角色必须**永活**（L0 呼吸是产品"活的"底线，20 §1.1）；为角色开"不可暂停"特权会破坏 App 框架一致性；
2. 角色消费**全局系统位**（唯一 LLM 人设位、默认 TTS 音色、待机画布、音频焦点联动），这些不是沙箱权限（8 位图）能表达的资源粒度；
3. 前台 App 语义：用户打开番茄钟时角色退居"角落徽章态"（stage 缩到 ~120×120 或隐藏，`exp_set_area()` 控制）——这是舞台自身的模式切换，不是 App 生命周期迁移。

落地形态：KShell 布局树常驻 `stage` 容器（默认全屏、App 前台时角标、设置页可关）→ `exp_attach(stage)` 挂接。表达子系统在 main 装配层与 kaleido_audio/kaleido_emotion 接线（glue code ≤300 行）。

### 4.4 口型同步与音频焦点联动

- **RMS→viseme**：音频输出路径（I2S 写回调或 esp_player 播放回调）按 20ms 窗算 RMS → 推入 lock-free 单值（最新值覆盖）→ express 在 LVGL tick 内 10-12Hz 采样，映射到 5 帧 viseme 的帧索引（对数分档）；连续 200ms 低能量回落 `silence_frame`。切换延迟预算 <80ms（承 20 §7-4，V 系列实测项；不达标退化为两帧开合，xiaozhi 同款简化）。
- **焦点联动**（架构 §3.2）：
  - 获得 `VOICE_CALL`（对话轮次）或 `TTS_ANNOUNCE`（点火播报）且播放流启动 → `exp_speaking(true)`（L2 激活、L1 情绪保留但口型层优先）；
  - barge-in（唤醒打断）→ 音频管线 flush（19 §4.3）伴随焦点内变化 → `exp_speaking(false)` 立即回落闭嘴帧 + 转 LISTEN 姿态（眨眼加速等微动作，表达"在听"）；
  - `MUSIC` 焦点（App 播歌）→ 角色保持 L0/L1，不出口型（可加轻微随拍摆动，二期彩蛋）。
- **TTS hint 下行**：ke_output.tts 的 rate/pitch/volume 偏移在装配 TTS 请求时叠加到 persona.voice.params 基线（百炼 CosyVoice 参数化支持，承 19 §2.1）；映射示例 `rate = base × (0.85 + 0.3×arousal)`、`pitch_shift = round(3×valence)` 半音、`volume = base + 10×arousal`（18 §4.2 查表插值的具体化，参数表冻结于固件、角色包可调基线）。

### 4.5 内存与性能预算（承 20 §6.2，逐项对号）

| 项 | PSRAM 占用 | 说明 |
|---|---|---|
| L0 图层缓存（8 层 460×460 RGB565+A8） | 1.0-1.5MB | 激活角色独占；切换时释放再分配 |
| L1 EAF 播放缓冲 | 423-846KB | 单/双缓冲可配（Kconfig）；20fps 全屏安全（20 §6.2） |
| L2 viseme 帧缓存 | ~150KB | 5 帧 × 120×120 局部（嘴部区域即可，无需全屏层） |
| express 任务栈 + 状态 | ~16KB 内部 RAM | 复用 LVGL 任务（不建独立渲染任务；EAF 解码在 esp_lv_eaf_player 内部） |
| **合计** | **≤2.4MB** | 超 23 号动画配额（0.9-1.8MB）上限 ~30% → 缓解：EAF 单缓冲 + Lottie 二期默认关闭；实测后回填 |

### 4.6 接口草案：kaleido_express.h（内核风格 C）

```c
/* SPDX-License-Identifier: MIT */
/*
 * kaleido_express.h — 角色形象与情感表达子系统公共 API
 *
 * 设计依据：docs/research/25-角色包与情感表达子系统设计.md §4
 *  - 四层合成状态机（承 20 号 §4.2）：L0 骨架 / L1 情绪 / L2 口型 / L3 动作
 *  - 情感输入承 18 号 §4.2 ke_output；EAF 播放内核 = esp_lv_eaf_player（vendor）
 *  - 非 KApp：舞台由 KShell 常驻提供，本组件在其内建对象树（25 号 §4.3）
 *
 * 线程模型：除注明外所有 API 仅可在 LVGL 任务上下文调用；
 * exp_notify_audio_level() 设计为音频回调上下文安全（无锁单值覆盖）。
 */

#pragma once

#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>

#ifdef __cplusplus
extern "C" {
#endif

#define EXP_API_VERSION 1
#define EXP_TAG_MAX 16          /* 情绪标签最大长度（23 词表最长词 + NUL） */
#define EXP_ASSET_PATH_MAX 96

/* ---- 系统态（最高优先级，直接抢占全层；承 esp_emote 事件模型 SYS/BAT）---- */
enum exp_sys_state {
	EXP_SYS_NONE = 0,
	EXP_SYS_CONNECTING,     /* 配网/云端连接中                     */
	EXP_SYS_LOW_BATTERY,    /* 低电（16 号电源阈值）                */
	EXP_SYS_OTA,            /* 固件升级中                           */
	EXP_SYS_OFFLINE,        /* 离线待机（L0 继续呼吸，L1 回落）     */
};

/* ---- 舞台区域模式（KShell 前台 App 协作，25 号 §4.3）---- */
enum exp_area_mode {
	EXP_AREA_FULL = 0,      /* 全屏 460×460（默认待机/对话）        */
	EXP_AREA_BADGE,         /* 角标 ~120×120（App 前台时）          */
	EXP_AREA_HIDDEN,        /* 隐藏（保留任务与资产，仅不可见）     */
};

/* ---- 事件回调（LVGL 任务上下文）---- */
enum exp_event {
	EXP_EVT_ACTION_DONE,    /* L3 一次性动作播完（payload=tag 序号）*/
	EXP_EVT_ASSET_MISSING,  /* 包索引的资产打开失败（payload=行号） */
	EXP_EVT_EMOTION_SETTLED,/* 防抖窗后情绪层实际切换（payload=tag）*/
};

struct exp_event_ctx {
	enum exp_event evt;
	int payload;
	void *user;
};

typedef void (*exp_event_cb_t)(struct exp_event_ctx *ctx);

/* ---- 配置与生命周期 ---- */

struct exp_config {
	uint32_t api;                     /* 须 == EXP_API_VERSION          */
	uint32_t stage_size;              /* 460                            */
	uint32_t transition_ms;           /* 情绪淡入淡出（默认 250）       */
	exp_event_cb_t cb;                /* 可为 NULL                      */
	void *user;
};

/**
 * exp_attach - 绑定舞台并初始化对象树（须在 LVGL 初始化后调用一次）
 * @stage: KShell 提供的常驻 LVGL 容器对象
 * @cfg:   配置（内部拷贝，可栈上分配）
 *
 * 返回 0 成功；-EINVAL 参数非法；-EALREADY 重复绑定。
 */
int exp_attach(struct lv_obj *stage, const struct exp_config *cfg);

/**
 * exp_register_assets - 装载角色动画资产索引（激活角色时调用）
 * @root: 角色包 assets/ 绝对路径（如 "/personas/com.kaleido.persona.momo/assets"）
 * @index: 解析后的 persona.json expression 段（kpersona 解析器产物）
 *
 * 懒加载：仅建索引与 L0 图层缓存；EAF 首播时 mmap。
 * 切换角色 = exp_unregister_assets() → exp_register_assets()。
 * 返回 0 成功；-ENOENT 必需资产缺失；-ENOMEM 图层缓存超配额。
 */
int exp_register_assets(const char *root, const struct kpersona_expression *index);
int exp_unregister_assets(void);

/* ---- 情感输入（双通道，25 号 §4.1 仲裁）---- */

/**
 * exp_set_emotion - LLM 通道：情感标签（23 词表，经 emotion_map 多对一收敛）
 * @tag:      "happy"/"sad"/"funny"...（未命中表则回落 neutral 并回调审计）
 * @intensity: 0-255；0 = 使用包内默认强度
 *
 * 锁存 30s；防抖 0.5-1Hz（内部仲裁，见 25 号 §4.1）。
 * 上下文：LVGL 任务。
 */
int exp_set_emotion(const char *tag, uint8_t intensity);

/**
 * exp_set_affect - 情感引擎通道：ke_output 心情态（1Hz 拍）
 * @valence: [-1,1]；@arousal: [0,1]；@persistence: [0,1]
 *
 * 内部按激活角色的 plane_map 查基础情绪 tag；LLM 锁存期内
 * 仅调制 intensity 不换 tag。
 */
int exp_set_affect(float valence, float arousal, float persistence);

/* ---- 口型与音频联动（25 号 §4.4）---- */

/**
 * exp_speaking - TTS 播放起停（由音频焦点 glue 驱动）
 * @on: true=VOICE_CALL/TTS_ANNOUNCE 播放中；false=打断/结束（立即闭嘴帧）
 */
int exp_speaking(bool on);

/**
 * exp_notify_audio_level - 播放流 RMS 电平（音频回调上下文安全）
 * @rms_255: 0-255 归一能量；内部 10-12Hz 采样映射 viseme 帧索引，
 *           连续 200ms 低能量回落 silence 帧。
 */
void exp_notify_audio_level(uint8_t rms_255);

/**
 * exp_listen - 倾听姿态（用户说话中：ASR 采集激活、角色收声）
 * @on: 由 VAD/唤醒事件驱动；仅调制 L0 微动作（眨眼加速），不抢 L1。
 */
int exp_listen(bool on);

/* ---- 动作 / 系统态 / 舞台 ---- */

/** exp_action - L3 一次性动作（"nod"/"cheer"...，播完自动回落，回调 ACTION_DONE）。 */
int exp_action(const char *tag);

/** exp_set_system - 系统态抢占/解除（EXP_SYS_NONE 解除）。 */
int exp_set_system(enum exp_sys_state st);

/** exp_set_area - 舞台区域模式切换（KShell 前台切换时调用，带 250ms 补间）。 */
int exp_set_area(enum exp_area_mode mode);

/** exp_tick - 骨架自治驱动（呼吸相位/眨眼调度）；由 LVGL timer 每帧调用，勿手动调。 */
void exp_tick(void);

/* ---- TTS hint 查询（语音链路装配请求时读取；承 18 号 §4.2 ke_tts_hint 落点）---- */

struct exp_tts_params {
	float rate;            /* 相对基线乘子   */
	int pitch_shift;       /* 半音，有符号   */
	int volume_offset;     /* 百分点         */
};

/** exp_get_tts_params - 按 ke_output 当前值查表（角色包基线 × 全局调制表）。 */
int exp_get_tts_params(struct exp_tts_params *out);

#ifdef __cplusplus
}
#endif
```

（注：`typedef exp_event_cb_t` 单项豁免——函数指针 typedef 提高可读性，记入 coding-style 豁免清单；其余结构体不新增 `_t` typedef，符合 constraints §6.3。`struct kpersona_expression` 定义于 kaleido_persona 组件头文件。）

**配套组件 kaleido_persona.h（要点，非全文）**：`kpersona_scan_root(path)`（枚举/校验，复用 KApp 扫描基建）、`kpersona_parse(json,len,out)`、`kpersona_activate(id)`（触发资产切换 + 情感快照加载 + prompt/voice 重装订事件）、`kpersona_active()`、`kpersona_enum(cb)`、`kpersona_delete(id)`（含云端克隆音色联动删除提示）。

## §5 资产生产管线与许可

### 5.1 出厂角色美术怎么来

**结论：AI 生成底图 + 人工拆层修型 + 程序化动作，"AI 直出分层 PSD"判定不可行（C 级评估）。**

- **AI 能做什么**：单张立绘（SDXL/即梦/Midjourney 出 460×460 角色正面全身/半身，风格统一）；嘴部/眼部关键帧变体的单帧生成（需 LoRA/参考图保持一致性，成功率中等）。
- **AI 不能做什么**：直接产出**结构化分层**（body/eyes×2/eyelids×2/brow/hair/acc 八层 + 每层的遮挡补全——闭眼帧要补眼皮遮挡区域的头发走向，viseme 帧要在同一张脸上换嘴）。当前生成模型无层级语义，分层一致性必须人工。
- **推荐管线（出厂角色）**：
  1. AI 出底图 3-5 张 → 美术选定 1 张；
  2. Krita/PS 人工拆 8 层 + 补遮挡 + 绘制闭眼帧×2、viseme 帧×5（同一源文件，一致性由图层保证）；
  3. 导出 PNG → 构建工具转 LVGL bin（RGB565+A8）；
  4. L1 情绪动画：**优先复用骨架**（程序化：happy=眉毛上移+身体微弹，程序参数进 persona.json 的 idle/微动作段，零美术成本）+ 少量 EAF（8 个情绪中挑 4-6 个表现力要求高的，AI 关键帧 2-4 张 + AE 补间出 GIF → esp32-gif.espressif.com 转 EAF，承 20 §5.2）；
  5. 美术预算估计（C 级）：底图+拆层+补帧 3-5 人日；6 个 EAF 情绪各 1-1.5 人日；合计 **10-14 美术人日**（1 个角色全量）。
- **降级档**（美术预算不足时）：出厂角色只用骨架程序动作 + 2 个 EAF（happy/sad）——产品仍完整可用（xiaozhi esp-vocat 已验证更简形态可用，20 §3）。
