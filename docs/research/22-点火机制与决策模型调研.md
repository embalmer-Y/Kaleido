## 结论先行（≤14 行）

1. **"jev" 大概率不是笔误**：TypeSafe AI 于 **2026-09-15** 发布了名为 **Jev** 的 "System One 决策模型"——输入状态、输出带校准概率的类型化决策（choice/score/noul 三种原语），官方定位就是"agent 控制的快速决策模型"，且已被 LangChain 官方博客介绍用于 agent harness。这与负责人"类似 jev 这一类**决策模型**"的措辞高度吻合（发布仅 6 周，属新热点）。备选解释 **JEPA**（LeCun 世界模型）词形相近但学界从不称其"决策模型"。**§0 有完整考证，需负责人最终确认**。
2. **Jev 不可上 MCU，但形态正是 Kaleido 云端裁决层想要的**：Jev 仅云端 API（美西）、70–500ms、输入 $0.042/MTok、输出免费；把"要不要主动说这句"做成一个 noul/score 问题正是其宣称的甜点区（路由/打分/agent 控制）。但它处于早期访问、单一供应商、无法本地部署——**建议借其"形态"，不绑定其"服务"**：本地打分器 + 云 LLM 裁决可以零供应商风险地复刻同一决策语义。
3. **JEPA 的诚实结论**：JEPA 是自监督表征学习/世界模型架构，直接用于 MCU 决策不现实（训练需大算力、推理需 GPU 级编码器、决策还要外加 MPC/actor 规划层）；可借鉴的只有思想——"预测误差→惊讶度→触发信号"，这与内在动机好奇心和 Galatea 情感引擎的预测误差驱动（报告 18）同源，作为长期方向记入。
4. **推荐双层架构（方案 A，2–3 周可落地）**：本地多因子显著性打分器（时间/事件/情感态/记忆新鲜度/用户在场，纯 C，CPU 占用可忽略）+ 滞回双阈值 + 冷静期 → 产生点火候选 → **云端一次 LLM 调用同时完成"要不要说+说什么"裁决与生成**（BYOK）。这同时是 Generative Agents、Open-LLM-VTuber、Replika 的实践共识：**门槛判断在端/便宜层，内容与礼仪判断在 LLM 层**。
5. **方案 B（G2/G3 演进）**：与 kaleido_emotion（报告 18，九维感受态）耦合的**驱力内稳态引擎**（孤独/社交欲等虚拟驱力自然推高 urgency 门）+ Generative-Agents 式记忆打分（云端 embedding 相关性 + 本地 recency/importance）+ 云 LLM 规划与每日反思。报告 18 §4.3 已给出三个现成判据（urgency>0.1 激活门、低唤起→慢环触发、多源动机仲裁）。
6. **业界频率基准**：Replika 主动 check-in 约**每天 1 次**；Open-LLM-VTuber 只做"空闲 N 秒即说"且**无频率上限/勿扰时段**（反面教材）；Moxie 靠脚本化任务表驱动。Kaleido 默认日上限建议 **4–8 次** + 最小间隔 20–30min + 勿扰时段，用户"主动度"0–10 旋钮统一缩放。
7. **成本可忽略**：方案 A 每次点火 = 约 1.2K 入/150 出 token；用 Gemini 2.5 Flash-Lite（$0.10/$0.40/MTok）每天 8 次约 **$0.04/月**；用 GPT-5.6（$5/$30）约 $2.5/月；Jev 若做预裁决约 $0.03/月。成本不是决策因素，**防骚扰与内容质量才是**。
8. **最大风险不是算法而是供应商生死**：Embodied（Moxie）2024-11 倒闭致全部云端机器人变砖——点火机制的"内容生成"可依赖云，但"何时想说话"的**决策内核必须在设备本地离线可用**（离线降级为本地模板问候）。

## §0 待确认项："jev" 的含义（需负责人确认原始所指）

### 0.1 候选一（可能性最高）：Jev by TypeSafe AI —— System One 决策模型

2026-09-15（距今 6 周）TypeSafe AI 结束两年隐身发布 **Jev**，自称首个 "System One Model"（取自 Kahneman《思考，快与慢》的 System 1；Jev 得名于经济学家 William Stanley Jevons）。核心事实：

| 维度 | 事实 | 证据 |
|---|---|---|
| 定位 | 不生成文本；输入非结构化 state，输出**类型安全的决策值 + 校准概率 + 置信度**，供代码直接分支。官方口号 "unstructured state in, typed probabilistic decisions out" | A：[发布博客](https://typesafe.ai/blog/introducing-system-one-models-and-jev)（访问 2026-10-25）+ [docs.typesafe.ai](https://docs.typesafe.ai/) |
| 三种问题原语 | **Choice**（选项概率）、**Score**（有序等级打分）、**Noul**（是非概率）；多个问题一次调用并行评估，"加问题几乎不增延迟" | A：docs.typesafe.ai + [LangChain 博客](https://www.langchain.com/blog/building-a-harness-with-jev) |
| 训练法 | RLCD（Reinforcement Learning for Calibrated Decisions），区别于 LLM 的 RLHF | A：发布博客 |
| 速度/成本 | 70ms–500ms 端到端（宣称比同级 LLM 快 40–200×）；输入 **$0.042/MTok、输出免费**；自评"快 193.6×、便宜 444.6×"（作者承认评测自制有偏） | A：发布博客 |
| 用例 | 智能分支/路由/打分/抽取、map-reduce、护栏（给 LLM 输出打分、越狱检测）、agent 循环中的快速判断点 | A：发布博客 + LangChain（ModelRouterMiddleware 模型路由、AutoModeMiddleware 工具风险拦截） |
| 部署 | **仅云端 API**（美西），无本地部署选项披露；早期访问（early access）阶段 | A：发布博客 |
| 局限 | 无字符串生成能力（不能替代 LLM 生成内容）；基数上限 255；厂商成立约 2 年、单一供应商、无 SLA 记录 | A/B |

**与 Kaleido 的契合点**：点火机制第二级裁决（"此刻、此情感态、此记忆依据下，要不要说？急不急？"）本质就是一个 Score/Noul 问题；Jev 的"便宜、快、校准概率"属性适合放在"本地打分器候选 → 云端裁决 → LLM 生成"的中间层。
**不契合点**：云端美西部署（RTT 150–250ms 可接受但依赖外网）；BYOK 语义不明（用户自带 key 体系外又引入一家供应商）；早期访问的存续风险高。

### 0.2 候选二（备选）：JEPA（Joint Embedding Predictive Architecture）

LeCun 主张的世界模型路线：I-JEPA（图像，arXiv:2301.08243，Meta 2023）/ V-JEPA（视频）在**潜空间**预测被遮蔽部分表征，避免逐像素生成的缺陷。**学界对 JEPA 的定性是"自监督表征学习/世界模型架构"，从不称其为"决策模型"**——决策需在其上外加规划层（LeCun 自述的 agent 图景：感知→世界模型→代价→actor，规划用潜空间 MPC/梯度优化）。
代表引文：[Turing Post: What Is JEPA?](https://www.turingpost.com/p/jepa)（B）、[I-JEPA 论文](https://arxiv.org/abs/2301.08243)（A）、[JEPA 教程（TechRxiv 2025，含 planning/决策章节）](https://www.techrxiv.org/doi/10.36227/techrxiv.176469421.19270944)（A，摘要页）。

**考证结论**：负责人原话"**类似 jev 这一类决策模型**"——Jev（TypeSafe）官方自我定位即为"决策模型（decision model）"且 6 周内获 LangChain/多家 AI 媒体报道，词形完全一致；JEPA 词形差一个字母且不称"决策模型"。**判 Jev（TypeSafe）为最可能所指，JEPA 为次选**。本报告 §2 两者均完整评估，请负责人一句话确认即可收敛。

## §1 需求定义

### 1.1 什么是"点火机制"（本报告工作定义）

设备在**空闲态**（无用户唤醒、无对话进行）自主完成三个决策并执行的机制：

1. **WHEN**（何时）：在什么时刻产生主动交互意图（时间节律、事件触发、内部状态越限）；
2. **WHETHER**（是否）：此刻该不该说（防骚扰裁决：用户在忙/勿扰/最近说过/内容不合适则放弃）；
3. **WHAT**（说什么）：以什么内容与口吻开口（与情感态连贯、有记忆依据，不是随机寒暄）。

输出还包括**不开口时的静默表达**（灯光/动画的微弱存在感），本文只覆盖"开口"路径，静默表达归 20 号动效报告域。

### 1.2 输入信号清单（Kaleido 硬件现实）

| 信号 | 来源 | 已有依据 |
|---|---|---|
| 时钟/日历 | RTC/NTP | 任务书 |
| 在场/移动 | IMU（静置=可能离开；被拿起=在场）、可选摄像头 | 报告 09/15 |
| 环境声/用户正在说话 | AFE/VAD（WakeNet 旁路可复用 AFE 通道） | 报告 02/05 |
| 情感态 | kaleido_emotion 九维感受态（1Hz，valence/arousal/urgency/social_bond 等） | 报告 18 §4 |
| 记忆新鲜度/相关记忆 | 设备端 JSONL 分层记忆 + 云端 embedding 检索 | 报告 21 |
| 交互历史 | 上次主动开口时间/结果（被回应/被忽略/被打断）、上次对话时间 | 本报告 §4 新增 |
| 用户设定 | 主动度旋钮、勿扰时段 | 本报告 §5 |

### 1.3 硬件/成本约束下的能力分界

- **设备端可跑**（ESP32-S31，320MHz 双核，C）：状态机、多因子打分器（浮点加权，<1KB 状态，CPU 占用可忽略）、驱力内稳态积分器（报告 18 已论证 kaleido_emotion C 可跑）、滞回/冷静期/令牌桶限频、规则引擎、JSONL 索引初筛。
- **云端跑**（BYOK，按 token）：embedding 检索精排、LLM 裁决与生成、每日反思摘要。
- **离线降级**：点火决策内核本地自治（可以不开口，或用本地模板问候），生成能力失联时不得卡死——继承 Moxie 变砖教训（§3.4）。

补充说明：

- **#1+#8 是共生关系**：打分器解决"何时产生候选"（cheap, always-on, offline），Jev 形态的裁决解决"候选是否值得说"（cheap-ish, online），LLM 解决"说什么"。三者各司其职，业界无一例外走此分层（§3）。
- **#2 的思想移植具体化**：在打分器中加一个"意外因子"——设备维护一个极简预测器（如"用户通常 19:00 回家/每天平均说 N 句话"），实际偏离预测的程度（预测误差）作为 novelty 输入 kaleido_emotion（其九维本就含 novelty 维，报告 18 §2.1）。这就是"类 JEPA"在 4KB RAM 里的诚实形态。
- **#3 与 #6 的关系**：主动推理的内稳态先验+期望自由能，在工程上收敛为"驱力误差积分+门限"，即 #6。若对外叙事需要理论背书，用主动推理语言描述方案 B 即可，不必实现贝叶斯机器。
- **#5 与 #6 的关系**：BDI 提供"意图"这个中间件——点火不是脉冲而是有生命周期的意图（产生→冷却→复活→过期→执行），防止"用户 5 分钟没理就反复点火"的抖动。

## §3 业界实现与论文证据

### 3.1 Generative Agents（斯坦福"小镇"论文）——记忆打分与主动性的标准范式 【A】

Park et al., *Generative Agents: Interactive Simulacra of Human Behavior*, UIST 2023（[arXiv:2304.03442](https://arxiv.org/abs/2304.03442)，全文经 [ar5iv](https://ar5iv.labs.arxiv.org/html/2304.03442) 核验，访问 2026-10-25）。与"何时主动想起某事"直接相关的是**记忆检索三因子**：

```
score(m) = α·recency(m) + β·importance(m) + γ·relevance(m)   （α=β=γ=1，各自 min-max 归一）
- recency:   指数衰减，每小时 ×0.995（最近访问的记忆得分高）
- importance: 记忆写入时由 LLM 按 1–10 打分（"喝水了"=1，"分手了"=9）
- relevance: 检索词 embedding 与记忆 embedding 的余弦相似度
```

**反思（reflection）机制**：最近 100 条记忆的 importance 总和 **≥150** 时触发一次 LLM 反思，生成更高阶推断（"Klaus 热衷于研究"）回写为新的、importance 更高的记忆——这是"主动性随重要事件积累而涌现"的量化机制。**规划（schedule）**：agent 每天生成日程并按观察动态重排。

**可移植性评估（对 Kaleido）**：
- recency（0.995^h）与 importance（1–10）：**本地可跑**（纯算术+小表）；
- relevance（余弦相似度）：向量在云端（报告 21 已设计云端 embedding BYOK + float16 缓存回 NAND，1 万条约 15MB，离线暴力扫描 ~1s）——Kaleido 的记忆检索可以**完整移植三因子公式**，这构成方案 B 的记忆打分层；
- 反思触发（importance 总和阈值）：本地可跑（ importance 在记忆写入时由云端 LLM 打好分存本地）；
- 注意：三因子论文里是"检索排序"用途；Kaleido 把它转义为"**此刻最值得提起的记忆**=三因子 Top-1 得分本身作为点火因子之一"——同一公式，两种消费方式，属设计推断【C】。

### 3.2 Open-LLM-VTuber——已源码级验证的主动消息机制 【A】

验证方式：GitHub API + raw 源码抓取（本机代理不可用，见方法说明）。仓库 [Open-LLM-VTuber/Open-LLM-VTuber](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber)。

- **触发侧（前端/客户端）**：官方文档（[Web Mode](https://open-llm-vtuber.github.io/en/docs/user-guide/frontend/web)，访问 2026-10-25）Setting→Agent 三项：①"允许 AI 主动说话"开关；②"空闲多少秒后允许主动说话"阈值；③举手/打断按钮手动触发（非思考-说话态时）。触发即 AI 从 idle 切换为主动发言。
- **执行侧（后端源码 `src/open_llm_vtuber/conversations/conversation_handler.py`）**：客户端发 `ai-speak-signal` 消息 → `handle_conversation_trigger` 加载 `proactive_speak_prompt` 工具 prompt（未配置则回退英文默认文案）→ 调 LLM，元数据 `{"proactive_speak": true, "skip_memory": true, "skip_history": true}`（跳过记忆与历史写入）→ 结果经 TTS 播报。
- **关键缺口（Kaleido 的改进空间）**：**无频率上限、无勿扰时段、无随机化、无用户反馈学习**——纯"空闲计时器"，是很好的最小实现参照但不是好产品范式。它证明了：主动开口在工程上=「一个信号+一个专用 prompt+一次 LLM 调用」，复杂度全在"何时发信号"。

### 3.3 xiaozhi-esp32——无官方主动交互 【B】

[78/xiaozhi-esp32](https://github.com/78/xiaozhi-esp32) 与乐鑫官方组件文档（[ESP-IoT-Solution 小智章节](https://docs.espressif.com/projects/esp-iot-solution/zh_CN/latest/ai/xiaozhi.html)）均以**唤醒词被动交互**（WakeNet 唤醒→流式对话）为主线，未提供官方"主动说话"功能；社区做法是固件加 FreeRTOS 定时器或经 MCP 服务端推送。对 Kaleido 的含义：**同硬件级别（ESP32+S3 级）尚无成熟主动交互先例，Kaleido 做本地点火决策是差异化点**，也意味着没有可直接抄的 C 参考实现。

### 3.5 学术研究：proactive agents / when to speak 【B】

- **Koala**（[arXiv:2501.17258](https://arxiv.org/html/2501.17258v1)）：群聊中 AI 参与控制，"when to speak"显式工作流；结论方向：时机判断需独立于内容生成的轻量通道。
- **When Should the Agent Speak? A Survey of Intervention Timing**（[OpenReview](https://openreview.net/pdf?id=b0yKEdAXEr)）：干预时机综述——信号流（场景变化/对齐检查）驱动。
- **Awesome Proactive Agents**（[GitHub: tao-hpu](https://github.com/tao-hpu/awesome-proactive-agents)）：该领域文献索引（含 Full-Duplex-Bench，毫秒级 when-to-speak/backchannel/barge-in 基准）。
- **驾驶场景 WoZ 研究**（[ACM DL](https://dl.acm.org/doi/full/10.1145/3828158.3833056)）："AI 能否知道何时说、何时闭嘴"——情境感知主动性的设计启示。
- 总体学术共识：主动性收益取决于**时机质量**而非频率；错误时机的打断比沉默伤害大（多篇 HCI 研究方向一致，具体单篇结论以 C 级记）。

### 3.6 内部证据：Galatea（项目内 A 级）

报告 18 已从源码确认三件可直接用于点火的判据（§4.3）：① `urgency > 0.1` 激活门；② 低唤起（arousal<0.1）或空闲 → 慢环深思/主动构思；③ 情感动机只是七源动机之一，须经仲裁不得独占。Galatea L07（workspace 慢环/显著性竞争/三时钟）是"类人脑思维点火"的最直接范本，报告 18 §6 已列为第 2 轮调研首位——本报告方案 B 的仲裁层按其思想设计。

## §4 候选架构设计

### 4.0 公共底座（两方案共享）

- 情感引擎：`kaleido_emotion`（报告 18 §4 接口：`ke_step()` 1Hz、`ke_output.ignition_candidate`、urgency 门）；
- 记忆系统：设备端 JSONL 分层 + 云端 embedding 检索（报告 21：本地 tag/时间初筛 + 云精排 + float16 向量缓存）；
- 点火机制新增组件：`kaleido_ignition`（ESP-IDF component，纯 C，消费 ke_output 与记忆索引，产出点火请求）。

### 4.1 方案 A：轻量工程版（本地多因子打分 + 云 LLM 裁决生成）

**数据流（文字版）：**

```
[1Hz 常驻环] 传感器(IMU/VAD/时钟) + ke_output(九维) + 交互历史(上次开口/被忽略计数)
      │
      ▼
 kaleido_ignition: 多因子显著性打分器
   S = w1·时间节律 + w2·情感动机(urgency/social_bond) + w3·记忆钩子(到期承诺/纪念日/三因子Top1)
       + w4·事件钩子(天气/日程/充电完成/长时间无互动) + w5·在场置信(IMU拿起/VAD人声)
      │  门控硬条件(AND)：勿扰时段外 ∧ 冷静期已过 ∧ 今日配额未用 ∧ 用户未在说话(VAD)
      ▼
 双阈值滞回: S > T_high → 产生点火候选（S 须回落 < T_low 才能再触发）
      │
      ▼  [联网时] 一次云调用（BYOK）：
 prompt = system(persona+情感JSON+主动度) + 记忆Top-3(云端检索) + 最近对话摘要 + 裁决指令
 LLM 返回: {"speak": bool, "urgency_1to5": n, "line": "...", "reason": "..."}
      │ speak=false → 记录 reason，S 惩罚性回落（学乖）
      │ speak=true  ▼
 TTS→播放 + 写点火日志(时间/S/各因子/LLM裁决/用户反应) + ke 侧记 KE_EVT_ACTION_RESULT
      │
      ▼ [离线时] 候选降级：仅 urgency 门(孤独驱力)越限且 >48h 未互动 → 本地模板问候(≤5条)
```

**接口定义（与既有报告对齐）：**

```c
/* kaleido_ignition.h 摘要（消费报告18 ke_output + 报告21 记忆索引） */
struct ki_factors {   /* 各因子 [0,1]，日志可观测 */
        float time_rhythm, affect_motive, memory_hook, event_hook, presence;
};
struct ki_decision {
        bool   candidate;        /* 滞回越限 */
        struct ki_factors f;     /* 供云端裁决 prompt 与日志 */
        uint8_t budget_used;     /* 今日已用配额 */
};
int ki_step(const struct ke_output *emo, const struct ki_context *ctx, struct ki_decision *out);
/* 云调用由上层 agent 发起：POST /ignite {emotion, f, memory_top3, last_dialog} → {speak,line,...} */
```

**成本模型（方案 A，每次点火 1 次调用，输入≈1.2K tok / 输出≈150 tok）：**

|---|---|---|---|---|
| Gemini 2.5 Flash-Lite | 0.10 / 0.40 | $0.00018 | $0.0014 | **≈$0.04** |
| DeepSeek V4-Flash | 0.14 / 0.28 | $0.00021 | $0.0017 | ≈$0.05 |
| Gemini 2.5 Flash | 0.25 / 1.50 | $0.00048 | $0.0038 | ≈$0.12 |
| GPT-5.6 | 5 / 30 | $0.0105 | $0.084 | ≈$2.52 |
| （可选）Jev 预裁决 | 0.042 / 0 | $0.000034（state≈0.8K tok） | 30 次评估/天 $0.001 | ≈$0.03 |

（价格为 2026-08 行业汇总页口径【B：[Spheron 定价对比](https://www.spheron.network/blog/llm-api-pricing-comparison-gpt-claude-gemini-deepseek-2026)、[pricepertoken.com](https://pricepertoken.com)】，上线前以官方页复核；BYOK 语义下此成本由用户 key 承担，对 BOM 为零。）

### 4.2 方案 B：进阶版（驱力内稳态 + 记忆打分 + 云规划）

**数据流（文字版）：**

```
[驱力层·1Hz·C] 虚拟驱力(每个=设定点+误差积分器+三级告警，Galatea drives.py 范本):
   social_bond(社交欲: 随无互动时长上升) / novelty(好奇: 预测误差喂入)
   / energy(电量真驱力) / care(用户久未倾诉)  → 误差注入 kaleido_emotion → urgency
      │
      ▼
[BDI 意图层·事件驱动·C] 愿望=驱力告警+时间节律+日程; 仲裁(多源加权, urgency 加权先占,
   每时刻至多 1 个活跃 Intention, 带 TTL 与复活计数——防抖动核心件)
      │
      ▼
[记忆打分层·云端为主] Generative-Agents 三因子:
   score=0.995^h·w_r + importance·w_i + cos_sim·w_g （云检索+本地 recency/importance）
   → "此刻最值得提的记忆" Top-3; 反思: 近 100 条 importance 和≥阈值 → 云端生成洞察回写
      │
      ▼
[云规划层] 一次 LLM 调用: persona + 九维情感 JSON + 驱力摘要 + 意图 + 记忆 Top-3
   → {speak, line, side_effects(记忆写入/情感 reappraisal 提案)}
   （reappraisal 走报告18 §4.4 受控通道，LLM 不得直写情感数值）
      │
      ▼
 播放 + 点火日志 + 用户反应回填(回应→social_bond 误差清除; 忽略→该类意图冷却×2)
```

**与 A 的差异**：候选的产生从"打分越限"升级为"驱力→情感→意图"的因果链（可解释为"它想你了所以开口"）；记忆从"钩子"升级为三因子打分+反思；仲裁显式化（BDI）。云端多两类调用：每日反思 2–3 次（输入≈2K tok/输出≈250 tok，Flash-Lite 下 < $0.03/月）与 embedding 检索（30 次/天×1.5K tok，按 $0.10–0.15/MTok 计 < $0.15/月）——**方案 B 月增量成本 < $0.2，仍可忽略**。

### 4.3 A/B 对比与迁移路径

| 维度 | A 工程版 | B 进阶版 |
|---|---|---|
| 落地周期 | 2–3 周（打分器+1 个云 prompt） | 6–10 周（驱力+BDI+反思管线） |
| 主动行为质感 | "定时+事件的智能闹钟，LLM 兜住内容质量" | "有内驱力的生物感，内容有记忆纵深" |
| 离线能力 | 完整（决策本地，生成降级模板） | 完整（驱力/意图本地，反思与生成降级） |
| 可解释性 | 因子表可观测 | 驱力→意图因果链可叙事 |
| 风险 | 权重拍脑袋→靠日志迭代 | 组件多、调参面大；需防"驱力刷子"（沿用报告18 有界调制纪律） |

**迁移路径**：A 的打分器中 `affect_motive` 因子就是 B 驱力层的退化形式（只读 urgency vs 自产误差）；A 的日志 schema 按 B 的驱力/意图字段预留——A 上线后用真实日志标定 B 参数，无需重写。

## §5 防骚扰与安全（两方案强制执行，产品红线）

1. **频率硬限**：令牌桶——默认日上限 **8 次**（用户 0–20 可调；Replika 基准≈1 次/天属极保守端）；**最小间隔 20–30 min**（冷静期）。
2. **勿扰时段**：默认 23:00–08:00（RTC 本地裁决，离线有效）；用户可改；勿扰期内候选一律丢弃（不排队到早上——"早上补说昨晚想说的"由记忆钩子在次日自然产生，更自然）。
3. **主动度旋钮**（0–10）：一个参数统一缩放 T_high、日上限、冷静期（0=完全被动）；设置项与"敢/怂"人格参数联动属后续 persona 域。
4. **上下文门（AND 硬条件）**：VAD 检测用户正在说话/环境多人声 → 不点火；IMU 表明正被持握移动（可能被携带）→ 只允许高 urgency；用户明确打断（barging-in）后 10 min 内不点火。
5. **负反馈学习（本地）**：被忽略 → 该意图类别冷却时间指数翻倍、对应记忆钩子降权；被回应 → social_bond 正向回填。**只学时机与主题权重，不学内容生成**（内容永远过云端裁决）。
6. **内容安全门**：`ethics_latched`（报告 18 极端负面闩锁）触发时禁用自由生成，只允许预置安抚模板 + 提示用户；深夜（勿扰边缘时段）禁用高唤醒内容（动画/音量上限走 ke_anim/tts hint）。
7. **点火日志**（NVS/NAND）：每次候选记录 `{t, S, 各因子, 裁决, 用户反应}`——既是调参数据也是用户可查的"为什么它找我"透明化依据（对齐报告 21 记忆可见可删原则）。
8. **云依赖隔离**：决策内核（1–5）全本地；云只做裁决与生成；云失联 ≠ 设备失能（Moxie 教训，§3.4）。

## §6 推荐与风险

### 6.1 推荐

1. **立即做方案 A**（本地打分器 + 一次云调用裁决生成），它同时是 Jev 形态的无供应商依赖复刻：noul("此刻该不该说")/score("急迫度") 的语义由 LLM 单次 JSON 输出承担；若日后 Jev 服务成熟且负责人确认采用，中间层可无缝替换为 Jev API（接口已在 §4.1 预留为 `/ignite` 一处）。
2. **方案 B 作为 G2/G3 演进**，先决条件：报告 18 kaleido_emotion 落地 + 报告 21 记忆管线落地 + Galatea L07/L08 第 2 轮调研（§7）。
3. **"jev" 待负责人确认**（§0）：若指 Jev(TypeSafe)→按上条作为可选云裁决后端并申请 early access 实测（延迟/中英混合 state 效果/价格复验）；若指 JEPA→采纳其"预测误差=惊讶=触发因子"思想（§2#2 已具体化），不引入任何 JEPA 模型本体。

### 6.2 风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|
| 打分器权重无先验，初期"要么闷要么烦" | 高 | 日志闭环（§5.7）+ 保守默认（日 4 次起步）+ 主动度旋钮兜底 |
| 云端裁决 prompt 质量（该不该说的礼仪判断不稳定） | 中 | 裁决与生成合一调用减少不一致；reason 字段入日志回归 |
| Jev（若采用）供应商风险：early access/单云/美西 RTT/停服 | 高 | 仅作可替换后端，接口收敛为 `/ignite`；不进 BOM 决策 |
| 用户对"它自己想说话"的隐私顾虑（一直在听？） | 中 | VAD 只出能量/是否人声特征不上云；点火日志本地可查可删 |
| 驱力系统参数失稳（驱力刷子/永远不触发） | 中 | 继承报告 18 有界调制+TTL+仲裁纪律；上线前仿真扫参 |
| 云 LLM 生成内容与情感态不连贯 | 中 | ke JSON 注入 system prompt + TTS/动画 hint 由 ke 查表垄断（报告 18 §4.4） |

## §7 第 2 轮建议

1. **Galatea L07 调研**（workspace 慢环/思维循环/显著性竞争/三时钟）——"类人脑思维的点火"最直接范本，为方案 B 的仲裁层取源码级细节（报告 18 §6 已列首位，本报告再次确认优先级）。
