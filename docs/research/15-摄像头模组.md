> 背景：2026-10-24 需求增补 ① 板载摄像头（拍照/视觉 AI）。本报告在报告 01（主控/GPIO 预算）、02（软件生态）、

## 结论先行（≤10 行）

1. **S31 摄像头接口核实**【官方确认】：走 **LCD_CAM 外设的 8-bit DVP 并口**（esp_cam_sensor 组件 SoC 支持表：S31 行
   LCD_CAM DVP=Y、MIPI-CSI=N/A、USB=Y、SPI=Y）；**不支持 MIPI**，选传感器必须限 DVP 版。旧驱动 **esp32-camera 不支持 S31**
   （README 仅列 ESP32/S2/S3），必须用新组件栈 **esp_cam_sensor v2.6.0 + esp_video**（esp-video 框架，S31 支持 DVP/SPI/USB
   视频设备 + **JPEG 硬件编解码 Y**）。
2. **主选：OV2640（200 万像素 DVP，片上 JPEG）**——esp_cam_sensor 驱动在列【官方确认】、模组生态最成熟
   （¥20–64 有据）、Mosaico 相机模块同代方案（OV3640/SC101IOT DVP）量产验证。**备选：SC2336 DVP 版（1080p）**，
   DVP 版模组渠道偏少；GC0308（VGA）为超低成本档。**OV5647/OV3660 在驱动列表中标 discontinued，按供货规则禁用**。
3. OV5640 AF（自动对焦）**首发不值得**：VCM 模组 ¥29.6–58 vs 定焦 ¥10–20 档，对焦耗时与功耗换来的收益在
   "自拍/识物/视频通话"场景有限；可作高配 SKU 选装。置信度：中。
4. **视觉 AI 生态**【官方确认】：esp-dl 模型库 Human Face Detect/Recognition、YOLO26（COCO 80 类）、COCO Detect/Pose/Seg、
   Hand Gesture、Pedestrian Detect、Cat/Dog Detect、**Speaker Verification（仅 S31/P4）** 均列 S31 支持；模型体积/内存占用
   未在索引页给出→逐模型 README 核实（风险 #4）。
5. **GPIO 影响**：DVP8 + XCLK + HREF/VSYNC/PCLK 共 **12 个专用脚** + RESET/PWDN 1–2 个 + SCCB 复用既有 I2C（0 新增）≈
   **13–14 个**。按报告 01 的 36/54 用量，加入摄像头后余量 18 → **约 4–5**：可行但需冻结引脚表；**TF 卡（+6 脚）不可同时
   承诺**，拍照存储落位 **NAND（BOM 已含 ≥128MB）**。
6. **电源影响**：OV2640 传感器 active 125–140 mW（datasheet）≈40 mA，模组级实测 90–110 mA；**3V3 轨按 +150 mA 预算**，
   参考 Korvo-1 用独立 2.8V/1.5V LDO 给摄像头做噪声隔离 + 负载开关彻底断电（隐私 + 省电双收益）。
7. **验证平台 Korvo-1 板载资源已核实**（§5）：双模拟麦→ES8389 codec→2×NS4150B 功放、DVP 摄像头连接器（OV3660 模组，
   媒体/社区双源）、4.3" 800×480 RGB LCD 子板、microSD 4-bit + NAND 预留焊盘、USB Type-A host——**可直接验证 DVP 摄像头 +
   JPEG 硬编 + esp-dl 全链路**。
8. 结构：镜头开孔 + 摄像头 FPC 避开模组天线净空区；**物理遮挡拨片为标配**（隐私）。
9. 整体置信度：**中高**（接口/驱动/模型支持均有官方文档；S31 PCLK 上限与模组 1k 实价待验证）。

## 二、详细分析

### 1. S31 摄像头通路核实【官方确认】

- **硬件接口**：ESP32-S31 datasheet v0.5 §4.2.1.5 定义 LCD_CAM 控制器（8/16/24-bit 并口，I8080/6800/RGB LCD 模式；
  无 SPI LCD 模式）——该外设在摄像头方向即 DVP 采样口（报告 01 已录）。esp_cam_sensor 组件页 SoC 支持表
  （列头 "MIPI-CSI / LCD_CAM DVP / USB / SPI"）S31 行：**N/A / Y / Y / Y**（来源 2）。
- **驱动栈**：S31 必须用 **esp-video-components**（`esp_cam_sensor` v2.6.0 传感器驱动 + `esp_video` v2.5.0 视频设备框架，
  V4L2 风格，`/dev/video2` 即 DVP 设备节点）（来源 2/3）。旧 esp32-camera 仓库 README 明确仅支持 ESP32/S2/S3，
  无任何 S31 字样（来源 5）——**社区大量 OV2640 例程基于 esp32-camera，不能直接搬到 S31**，需走 esp_video API。
- **PCLK/分辨率上限**：ESP-FAQ 给出 ESP32=8 MHz / S2=32 MHz / S3=40 MHz 的 DVP 时钟参考，**S31 数值未披露**【待验证】
  （风险 #2）。分辨率上限的实践约束（esp_cam_sensor 页对 S3 的注释原文）："2MP only possible for still images with
  ov2640\ov3660\ov5640 outputting jpg format"——即 **2MP+ 必须用传感器片上 JPEG 输出**，RAW 大分辨率受 PSRAM 带宽限制；
  S31 同为 LCD_CAM 代际 + 16MB in-package PSRAM，推断同口径（设计推断）。
- **JPEG 硬件编解码**：esp_video SoC 表 S31 行 JPEG HW Enc=**Y** / JPEG HW Dec=**Y**（来源 3）——RAW 拍照可走硬件编码，
  与 constraints §6.7"默认渲染路径必须使用 PPA 与 JPEG 硬件编解码"一致。
- **引脚占用（DVP 8-bit 标准配）**：D0–D7（8）+ PCLK + VSYNC + HREF + XCLK = **12**；SCCB（SDA/SCL）复用既有 I2C 总线
  （SCCB 兼容 I2C，地址 0x30 级，避开 0x50 EEPROM/触摸/IMU 即可）；RESET/PWDN 可合并 1 脚。合计 **13 个新 GPIO**。
  先例：Mosaico 相机模块插左槽时 GPIO14 改作 DVP D4（来源 24）；Korvo-1 NAND 与 microSD 共享 GPIO20–25（来源 7），
  证明乐鑫自己也在做引脚复用。
- **XCLK**：摄像头需 16/20 MHz 级主时钟（社区通行值【社区经验】），S31 经 GPIO Matrix 时钟输出（CLK_OUT/LEDC）可产生；
  Korvo-1 摄像头连接器含 XCLK 脚（来源 7），说明官方参考设计已解决，抄其引脚表即可（板在手，直接读丝印/原理图）。

### 2. 传感器候选分析

- **OV2640（主选）**：2MP、1/4"、片上 JPEG（UXGA@15fps 压缩模式功耗 140 mW，datasheet；standby <1 mA、deep standby
  <15 µA）。十年经典料，esp_cam_sensor 与 esp32-camera 双栈在列。模组价格：淘宝通用模组约 ¥20–35（来源 15）、
  微雪成品板 ¥64.26（立创在售，来源 14）。**1k 档 FPC 裸模组估价 ¥4–8**【待验证】（1688 渠道询价，风险 #3）。
  视频通话 VGA/720p MJPEG、人脸检测输入 240×320 级、拍照 UXGA——掌机场景全覆盖。
- **SC2336（备选）**：SmartSens 1080p 新款，esp_cam_sensor 在列（MIPI & DVP）【官方确认】。注意 **S31 无 MIPI**，必须
  采购 DVP 版模组：淘宝晶视 ¥85 为 MIPI 版（来源 19），AliExpress 有 24pin FPC 2MP $6.01（接口版本需与卖家确认，
  来源 20）；1688 DVP 批发"通常低于 ¥30/片"【供应商声称】。画质优于 OV2640（背照式），但 DVP 供货渠道是主要风险。
- **SC101IOT**：Mosaico V1.4 PCB 相机模块同款（1024×768，来源 24），乐鑫生态背书；无片上 JPEG → 高分辨率/帧率受限
  （esp32-camera issue #573 官方答复：需高分辨率/帧率时选带 JPEG 的传感器，来源 23）。作为跟随 Mosaico 生态的兜底。
- **GC0308**：VGA 超低成本档（裸芯片 ¥4.28–4.50，1688；DVP 模组 ¥28.78，来源 21/22），1/7" 10-bit ADC 内置 ISP
  （来源 22）。若产品定位只需"识物/二维码/人脸有没有"级视觉，可再省 ¥2–4；但拍照体验差，与掌机定位不符，仅记录。
- **OV5640 / OV5640 AF**：5MP DVP + 片上 JPEG + 可选 VCM 自动对焦。AF 成品模组淘宝 ¥29.6 起、1688 DECXIN ¥58、
  微雪 AF+闪光灯板 ¥143（来源 16/17/18）。**评估：不值得首发**——① 掌机拍照主力是"自拍/识物/文档"，主体距离多在
  0.3–1.5 m，定焦足够；② VCM 对焦需要时间（百 ms 级）与额外电流，抓拍体验反而变差；③ BOM 差价 ¥10–30 挤占 $50
  工作预算（R2：音频优先）。留作"高配/开发者 SKU"选装（FPC 连接器同 24pin，可后兼容）。
- **OV5647 / OV3660 淘汰理由**：esp_cam_sensor 传感器表标注 discontinued（来源 2）；constraints §4.3 禁用 EOL/NRND 料。
  （注：Korvo-1 官方搭配 OV3660 属既成事实的官方库存选择，不代表新设计可跟进。）

### 3. 视觉 AI 生态（ESP-DL 对 S31）【官方确认，来源 10】

esp-dl `models/README.md` 模型表，S31 在列的：YOLO26（COCO 80 类 NMS-Free 检测）、COCO Detect/Pose/Seg、
Human Face Detect（MSR/MNP/ESPDet）、Human Face Recognition、Cat/Dog/Hand Detect、Hand Gesture、Imagenet Cls
（MobileNetV2 1000 类）、Pedestrian Detect、**Speaker Verification（仅 S31 与 P4——音频+视觉同芯的差异化点）**、ReID；
Motion Detect / Color Detect 全系可用；**OCR 仅 P4**（S31 无 ISP，排除）。模型存放位置 Flash/PSRAM/SDCard 可经
menuconfig 配置（README 原文）。**各模型体积与推理时延未在索引页披露**→逐模型 README/S3 实测值换算（风险 #4）；
参考系：esp-sr WakeNet10 RAM 16 KB + PSRAM 523 KB（报告 02，S3 实测）——PSRAM 16MB 下人脸检测+唤醒词并发可行，
但需在 G2 前跑内存高水位审计（复用报告 02 的固件先行清单，追加摄像头 demo 项）。

### 4. 拍照存储与视频通路

- **存储**：拍照链 DVP→PSRAM 帧缓冲→（传感器片上 JPEG 或 S31 JPEG HW Enc）→**NAND（GD5F1GM7 类 128MB，BOM 已含，
  报告 01/14）** FATFS 落盘。TF 卡与 NAND 在 Korvo-1 上共享 GPIO20–25（来源 7）——**Kaleido 不承诺 TF 卡**（GPIO 不够，
  见结论 5）；NAND 128MB≈UXGA JPEG（300 KB 级）约 300–400 张，规格书标称容量若不够可升 256MB 档（V-06 一并询）。
- **视频通话/图传**：VGA@15–20fps MJPEG ≈ 1–2 MB/s，Wi-Fi 6（150 Mbps PHY，报告 01）带宽充裕；JPEG HW Enc 在
  esp_video 中已是设备节点（/dev/video10），链路软件化即可【设计推演，G5 实测帧率】。

### 6. 对整机的影响（电源/结构/隐私）

- **电源**：3V3 主轨 ≥2 A（报告 08）余量充足，按 **+150 mA**（模组级 100–110 mA + LDO 损耗）预算；建议摄像头
  供电挂独立 LDO 或经负载开关（① 隔离传感器噪声与射频突发；② 拍照外彻底断电，静态 0 mA——模组级待机常达
  数十 mA，社区实测，来源 13）。睡眠态摄像头必须断电而非 standby（功耗表写入 power-budget 文档）。
- **结构（kaleido-mech 需求）**：① 镜头开孔 Ø≥3 mm（视模组 FOV 与外观圈），位置避开握持区与天线净空区；② 摄像头
  FPC 走线**禁止穿越模组天线净空区下方**（constraints §5.4），建议镜头靠主板中轴线布置；③ 预留遮挡拨片导轨槽
  （见下）；④ 增补后整机允许更大更厚，摄像头高度（模组 Z 高 ≤3.5 mm 级）不构成厚度瓶颈。
- **隐私**：**物理遮挡拨片为标配**（滑动式，盖住镜头+微动开关联动 UI 状态），成本 <¥1【估算】；这是 AI 拍照设备的
  信任卖点，对齐笔记本摄像头遮蔽惯例【社区经验】。纯软件断电不作为隐私承诺。
