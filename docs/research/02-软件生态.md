## 结论先行

1. **ESP-IDF 最新稳定版为 v6.1（2026-08-27 发布）**，v6.0 线最新补丁 v6.0.3（2026-09-02）；ESP32-S31 在 v6.1 中为 **preview 支持**，官方文档站已有完整 `esp32s31` target（Get Started/API 参考）。**推荐锁定 v6.1**（置信度：高，【官方确认】）。
2. **Arduino 稳定线不支持 S31**：3.3.12（IDF v5.5.5）无 S31 target；仅预发布 4.0.0-RC1（IDF v6.1）的 variants 目录出现 `esp32s31`。项目"禁用 Arduino"约束可执行且无损失（置信度：高，【官方确认】）。
3. **ESP-SR 自 v2.4.4 起 Support ESP32-S31**（CHANGELOG 原文），最新 v2.6.0 中 WakeNet/MultiNet(mn7)/AFE 三模块均含 S31（标注 preliminary，2026-05-09）；WakeNet10 参考内存 RAM 16KB + PSRAM 523KB、CPU 单核约 20%（S3-Korvo 实测，S31 复用同构数据）（置信度：高）。
4. **显示栈可用**：官方组件 espressif/esp_lcd_sh8601（SPI&QSPI）与 espressif/esp_lcd_co5300（SPI&QSPI&MIPI-DSI）均声明"支持所有 targets"；rm67162 仅有社区组件；S31 的 **PPA（SRM/Blend/Fill）与硬件 JPEG 编解码（esp_driver_jpeg）在 IDF v6.1 文档齐备**；esp_lvgl_port 2.9.0 支持 LVGL 8/9（置信度：高；QSPI 在 S31 的实际吞吐【待验证】）。
5. **音频栈**：S31 双 I2S，新驱动 i2s_std/i2s_pdm/i2s_tdm 齐备；**PDM 不支持全双工**（收发时钟不同），采放需分置两个 I2S 控制器；**ASRC 在 S31 的 IDF 文档中无独立驱动页**（仅 `i2s_channel_tune_rate()`，与 start.md "芯片有 ASRC" 的说法冲突，【待验证】）；esp_codec_dev 1.6.2 **不含 TAS5805M/MA12040P**，功放需自写 I2C 初始化驱动（置信度：高）。
6. **esp-adf 不引入**：v3.0 重写中（基于 ESP-GMF），仅声明要求 IDF v5.5.2+，v2.x 仅收 bugfix；本项目直接用 IDF v6.1 + esp_codec_dev + esp-sr 更轻。
7. **云端 LLM 对话参考实现首选 xiaozhi-esp32**（31.8k stars，MIT，v2.5.2 于 2026-10-11 发布）：WebSocket + MQTT/UDP 双通道、Opus 流式、MCP 协议，**main 分支已含 3 个 S31 板型（要求 IDF ≥ 6.1）**；未发现乐鑫官方对标 S31 的开源方案（置信度：高/【待验证】）。
8. 总体风险：**S31 在 IDF v6.1 / esp-sr / xiaozhi 中均处 preview 或初步支持状态**，样机前必须用 ESP32-S31-Korvo-1 等官方 devkit 完成"固件先行验证清单"（见文末）。

## 逐项分析

### 1. ESP-IDF v6 与工具链、Arduino 现状

**版本状态【官方确认】**（GitHub Releases 页，访问 2026-10-23，来源 [1]）：
- **v6.1（2026-08-27）为当前 Latest 稳定版**，是 v6.0 的小版本升级（应用层基本兼容）；v6.0 线最新补丁 **v6.0.3（2026-09-02）**。
- 其余活跃分支：v5.5.6（2026-10-16）、v5.3.6、v5.2.8（v5.2 线已于 2026-08 EOL）。
- v6.1 破坏性变更需留意：LCD 颜色 API 统一为 FourCC 格式、GPIO API 更名、esp-mqtt 移交组件管理器、mbedTLS 升 4.1.0 等。

**ESP32-S31 支持情况【官方确认】**：
- v6.1 系列发布说明（v6.1 / v6.1-rc1 / v6.1-beta1）明确写入 "**Added preview support for ESP32-S31**"（来源 [1]）。（注：检索摘要曾提示 v6.0 亦提供 S31 preview，但 Releases 页面仅 v6.1 系列注记可见 S31 字样，以 v6.1 为准。）
- 文档站 stable（v6.1）已有独立 `esp32s31` target 的完整文档：Get Started（来源 [2]）、编程指南首页（来源 [3]）、外设 API 参考（来源 [4]，含 LCD/I2S/PPA/JPEG 等）。Get Started 页未再出现 "preview/experimental" 字样，仅说明提供编译 S31 代码的工具链；**工具链具体构成（riscv32-esp-elf 版本）文档页未列出，属【待验证】**（用 `install.sh` 安装时确认）。
- 芯片规格：双核 RISC-V @ 320MHz、Wi-Fi 6 + BT 5.4（来源 [25]，官网产品页经检索摘要转引；直连 .cn 站点 403）。ESP32-S31-WROOM-3 模组 = 16MB Flash + **16MB 八线 PSRAM**（来源 [24]，xiaozhi Korvo S31 板卡 README）；**32MB PSRAM 模组选项【待验证】**（查模组 datasheet / ESpressif 官网模组页）。

**Arduino 现状【官方确认】**（来源 [23]）：
- 稳定版 **3.3.12（2026-09-18）基于 ESP-IDF v5.5.5，无 S31 支持**；
- 预发布 **4.0.0-RC1（2026-09-23）基于 ESP-IDF v6.1**，GitHub API 检查其 `variants/` 目录确认**存在 `esp32s31`**（408 个 variants 中含 esp32s31），且 RC1 注记含 "Fix UAC Multi Rate example for S31"——即 Arduino 对 S31 的支持已起步但仍在 RC 阶段（RC1 中 Matter/ESP_SR 等组件曾因 IDF6 不兼容暂缺，Matter 后补）。
- **对本项目**：约束"仅 IDF v6、禁用 Arduino"与现状吻合，无需动摇；即使未来想用 Arduino 也是 4.0.0 正式版之后的事。

### 2. ESP-SR / WakeNet / MultiNet

**版本与支持矩阵【官方确认】**（ESP Component Registry esp-sr 页，来源 [9]，访问 2026-10-23）：
- 组件最新版 **v2.6.0**（约两周前上传；总下载 170 万次）；GitHub tag 停留在 v2.0.0（来源 [10]），**esp-sr 以组件仓库为版本源**。
- **CHANGELOG：v2.4.4 "Support ESP32-S31"**（来源 [10]，GitHub master 分支 CHANGELOG.md）。
- 支持矩阵（v2.6.0 README）：
  - WakeNet：ESP32/S2/**S31**/S3/P4/C3/C5/C6；
  - MultiNet：S3/P4/**S31**（S31 仅 **mn7_cn / mn7_en**；S3 另有 mn5q8/mn6）；
  - AFE：ESP32/S3/P4/**S31**。S31 标注为 **preliminary target support（2026-05-09）**。
- ESP-SR 文档站已有 **esp32s31 target 专区**（含独立 PDF `esp-sr-en-master-esp32s31.pdf`，来源 [11][12]），AFE 能力：AEC、VAD(VADNet)、BSS、NS、NSNET 深度降噪；2026-04-28 新增全双工 AEC，2026-08-28 新增 GSC 波束成形 + DOA（来源 [9]）。语音链路为 16kHz/单声道/16bit，帧宽步长 30ms（来源 [12]）。

**唤醒词可用清单【官方确认】**（v2.6.0 唤醒词模型矩阵，来源 [9]）：wn9/wn10 系列含 Hi,乐鑫、Hi,ESP、你好小智、小爱同学、Alexa、日语/法语/德语/西语/葡语唤醒词。其中 **"你好小智"（wn9_nihaoxiaozhi_tts / wn10_nihaoxiaozhi）** 与 xiaozhi 生态天然配套。**S31 上逐个模型的可用性【待验证】**（文档页 WakeNet9/9l 行文仍写 "支持 ESP32/S3/P4"，以编译矩阵实测为准）。

**内存/性能占用【官方确认，数据为 S3 实测】**（esp-sr 文档 esp32s31 target benchmark 页，来源 [13]；页面注明数据在 **ESP32-S3-Korvo V4.0** 上测得）：
- WakeNet10（3 通道，DET_MODE_3CH_90）：**RAM 16KB + PSRAM 523KB**，单帧 6.4ms，**单核 CPU 约 19.9%**；
- WakeNet9l 资源约为 WakeNet9 的 1.3 倍（来源 [9]）；
- MultiNet mn7：无公开内存数字（3 米安静环境命令词准确率 97.2%）；AFE/VAD 资源表为空。**S31 实际占用需实测（CPU/PSRAM 与 S3 同级，但需确认 PIE/SIMD 指令等效）【待验证】**。

**esp-skainet 示例工程参考价值【官方确认】**（来源 [14]，仓库活跃，最近 push 2026-10-12）：
- 官方离线语音助手示例工程（990 stars）：`wake_word_detection`（WakeNet9，推荐入门）、`cn/en_speech_commands_recognition`（MultiNet7）、`chinese_tts`、`usb_mic_recorder`；
- **master 分支无任何 S31 板级配置**（GitHub tree 全文检索 "s31" 为 0 命中），板卡覆盖 ESP32-Korvo / S3-Korvo / ESP-BOX / S3-EYE / P4-Function-EV；README 声称支持 IDF v4.4/v5.0（偏旧）；另有 `dev/2.0` 分支在开发。
- **结论**：esp-skainet 作参考（AFE 配置、命令词添加流程、TTS），**不可直接作为 S31 工程模板**；S31 板级移植需自建（xiaozhi 的 S31 板型反而是更接近的起点）。

### 3. 显示驱动栈（QSPI AMOLED / PPA / JPEG / LVGL）

**esp_lcd 框架与 S31【官方确认】**（IDF v6.1 esp32s31 LCD 文档，来源 [8]）：S31 LCD 支持 SPI/I2C/I80/RGB 接口（含 Parallel IO 模拟 SPI/I80）、DMA 后台刷写（`esp_lcd_panel_io_tx_color` + `on_color_trans_done`）、YUV↔RGB 色彩转换、FourCC 颜色格式（v6.1 统一）。**注意：S31 的 LCD 文档索引未明示 "QSPI" 字样，QSPI 面板走 SPI 驱动的 quad 模式由面板组件层实现**（`use_qspi_interface` 配置项）。

**QSPI AMOLED 面板驱动组件【官方确认】**（ESP Component Registry，访问 2026-10-23，来源 [15][16][17][18]）：
- **espressif/esp_lcd_sh8601 v2.0.1~1**：官方组件，SPI & QSPI（`.use_qspi_interface=1`），16/18/24bpp，声明 "Supports all targets"（含 esp32s31）；LVGL 注意点：绘制坐标需偶数对齐（LVGL8 需 `rounder_cb`，LVGL9 用内置对齐机制）；
- **waveshare/esp_lcd_sh8601 v2.0.0**：微雪维护，下载量 120 万（1.8 寸 AMOLED-1.8 即 SH8601）；
- **espressif/esp_lcd_co5300 v2.2.0**：官方组件，SPI & QSPI & MIPI-DSI，下载 74.6 万（2 寸 AMOLED 常见控制器）；
- **rm67162：官方 espressif 组件不存在**（registry 检索仅 1 结果）——只有社区 **crosser/esp-lcd-panel-rm67162 v0.9.1**（Apache-2.0，292 下载，含 LVGL demo，上传 3 周）；另有社区 idoc/esp_lcd_rm690b0 v1.0.0（QSPI 已测）。
- **选型建议**：鱼鹰 2 寸 QSPI AMOLED 确认控制器型号后：SH8601/CO5300 → 用官方组件（高置信）；RM67162 → 社区组件或按 datasheet 自写（低风险可控，QSPI 时序与 sh8601 类似）。面板型号确认前此项保持【待验证】。

**PPA 2D 加速【官方确认】**（IDF v6.1 esp32s31 PPA 文档，来源 [7]）：
- 三类操作：`ppa_do_scale_rotate_mirror()`（双线性缩放 1/16 精度 + 90° 整数倍旋转 + 镜像）、`ppa_do_blend()`（两块 alpha 混合，支持 color key）、`ppa_do_fill()`；
- 限制：无通用 blit；SRM 输入输出缓冲不可同址；输出需 cache line 对齐（16 字节对齐，flash 加密时行宽也需对齐）；**SRM 不能工作于加密外部内存**；每个 client 只支持一种操作；回调运行在中断上下文。UI 层用 PPA 做旋转/缩放/合成时按这些约束设计渲染管线。

**JPEG 硬件编解码【官方确认】**（IDF v6.1 esp32s31 JPEG 文档，来源 [6]）：
- S31 内置 JPEG 硬件 codec，驱动组件 **esp_driver_jpeg**（`driver/jpeg_encode.h` / `jpeg_decode.h`）；**编/解码引擎同一时刻只能一个方向**；
- 能力：解码 YUV444/422/420→RGB565/RGB888；编码 RGB565/RGB888→Baseline JPEG（质量 1-100）；1080×1920 解码约 28fps / 编码约 25fps（CPU 360MHz + PSRAM 200MHz 条件下）——2 寸屏（典型 412×412 或 320×240 级）绰绰有余；
- 限制：PSRAM 加密时缓冲须位于非加密区（CONFIG_SPIRAM_ENC_EXEMPT）；缓冲须经 `jpeg_alloc_*_mem()` 分配；编解码期间持有频率锁阻止 light-sleep。
- 软件方案 **esp_new_jpeg v1.0.2** 支持全部 targets（含 S31），可作硬件不可用时的回退（来源 [20]）。

**LVGL【官方确认】**（来源 [19]）：**esp_lvgl_port v2.9.0**（约 2 个月前上传，总下载 170 万）同时支持 **LVGL 8 与 LVGL 9**（默认最新），声明 "Supports all targets"，并提到软旋转可借 PPA 加速（文档以 P4 为例）。**建议 LVGL 9.x**（v6.1 的 FourCC 颜色 API 与 LVGL9 格式模型更契合）。

### 4. 音频栈（I2S / PDM / ASRC / codec / esp-adf）

**I2S 新驱动【官方确认】**（IDF v6.1 esp32s31 I2S 文档，来源 [5]）：
- S31 含 **2 个 I2S 控制器**；驱动为通道句柄式新 API：`i2s_std` / `i2s_pdm` / `i2s_tdm`（`i2s_new_channel` + `i2s_channel_init_*_mode`），全 API 线程安全。
- **PDM 麦采集**：PDM RX 仅在 I2S0，支持两种格式——硬件 PDM→PCM 转换（16–48kHz，配 `I2S_PDM_RX_SLOT_PCM_FMT_DEFAULT_CONFIG`）或原始 PDM 流（1.024–6.144MHz）；降采样 64x/128x 可选；位宽固定 16bit；内置高通滤波（23.3–185Hz）与 1–15 倍数字增益；`dins[4]` 可多线。
- **关键限制：PDM 不支持全双工**（TX/RX 时钟不同）→ Kaleido 架构应为 **I2S0-PDM-RX（麦）+ I2S1-STD-TX（功放/codec）**，正好用满 2 个控制器。
- 运行时速率微调 `i2s_channel_tune_rate()` 可对齐生产/消费速率（近似 ASRC 用途）。
- **ASRC【待验证】**：S31 外设文档**无独立 ASRC 页面**（来源 [4] 复核确认），I2S 文档亦无 ASRC 章节；start.md 中"芯片有 2×I2S + ASRC"的说法与当前文档不符——需查 S31 TRM/数据手册确认是否有硬件 ASRC 模块（验证手段见风险表）。

**esp_codec_dev【官方确认】**（组件页 v1.6.2，另有 2.0.0-beta5 预发布，总下载 220 万，活跃维护；来源 [21]）：
- 支持芯片表：录放（ES8311/ES8388/ES8374/ZL38063/ES8389/CJC8910）；仅放（TAS6805M*、AW88298、ES8156）；仅录（ES7210/ES7243/ES7243E）。(*页面原文为 "TAS6805M"，疑为 TAS5805M 之笔误，以源码为准。)
- **TAS5805M 与 MA12040P（仓库根目录两份数据手册对应型号）均不在支持列表** → 这两款 I2S 输入数字功放需自写驱动：I2C 初始化/采样率配置 + I2S 数据直通，工作量可控（datasheet 已在仓库：tas5805m.pdf、ma12040p.pdf）。备选：若选型改为表内芯片（如 AW88298）可免自研。
- 组件声明 "Supports all targets"，含软件音量、PA-only dummy codec 模式。

**esp-adf 现状【官方确认】**（来源 [22]，2.3k stars）：master 分支为 **ADF v3.0 大重写**（基于 ESP-GMF 多媒体管线，与 v2.x 完全不兼容），要求 **ESP-IDF ≥ v5.5.2**（未声明 v6 适配）；`release/v2.x` 仅收 bugfix。**结论：本项目不引入 esp-adf**——语音链路由 esp-sr + 自研/移植 WebSocket 客户端即可，避免拖入巨型框架与其 IDF 版本耦合。

### 5. 云端 LLM 语音对话参考实现

**xiaozhi-esp32（虾哥小智）【官方确认，仓库证据】**（来源 [24]，访问 2026-10-23）：
- **规模与活跃度**：31.8k stars / 7.4k forks，1160 commits，629 open issues，Discord + QQ 群，Discussion 活跃；最新 release **v2.5.2（2026-10-11）**（另 v2.5.0 2026-09-10、v2.4.2 2026-08-06）——**周/月级迭代，社区活跃度极高**。
- **架构**：开源 MCP 化 ESP32 语音助手，云端 LLM（Qwen/DeepSeek 等）；**双传输通道：WebSocket 与 MQTT+UDP（混合协议）**；音频 **Opus 流式**；ASR+LLM+TTS 管线或 Realtime 端到端语音模型；支持 AEC 硬件上的全双工；设备端 MCP（音量/LED/IO 控制）+ 云端 MCP（智能家居/PC/搜索/邮件）；默认连 xiaozhi.me 官方服务器，社区另有 Python/Java/Go 开源服务端。
- **IDF 要求**：README 明确 **需要 ESP-IDF v6.0.1+，推荐 release/v6.1，IDF 5.x 不支持**（MQTT/BluFi 加密已迁移 PSA Crypto）——与本项目"锁定 IDF v6"完全一致。
- **S31 适配【官方确认，代码证据】**：main 分支 138 个板型目录 / 171 个构建变体中，GitHub tree 检索到 **3 个 S31 板型** + `sdkconfig.defaults.esp32s31`：

## 风险与待验证项

| # | 风险/缺口 | 等级 | 验证手段（固件先行验证清单） |
|---|---|---|---|
| 1 | S31 在 IDF v6.1 为 **preview** 支持，API 可能随 v6.2 演进 | 高 | 样机前先用 **ESP32-S31-Korvo-1 devkit** 跑通 `idf.py set-target esp32s31` + hello_world + Wi-Fi/PSRAM 压力测试全流程 |
| 2 | esp-sr S31 为 preliminary，benchmark 数据出自 S3 板 | 高 | devkit 上编译 esp-sr `wake_word_detection`（chinese_tts 亦可选），实测 RAM/PSRAM/CPU 占用与唤醒率 |
| 3 | S31 上逐个唤醒词模型（wn9/wn10 各语言）可用性未逐一确认 | 中 | 用 `CHOOSE_WAKE_WORD` 枚举编译矩阵（hilexin/hiesp/nihaoxiaozhi/alexa）逐一 build+烧录测试 |
| 4 | QSPI AMOLED 在 S31 的 esp_lcd quad 模式吞吐未实测（组件声明 all targets，但 S31 LCD 文档未明示 QSPI） | 高 | devkit + 鱼鹰面板（或微雪 AMOLED-1.8/2.06）跑 esp_lcd + esp_lvgl_port 点亮，测 LVGL fps 与 PSRAM 带宽占用 |
| 5 | PPA/JPEG 与 PSRAM 加密互斥、对齐限制（若启用 flash 加密量产） | 中 | 先在未加密配置下跑 PPA fill/blend + JPEG decode demo；启用加密后复测 SPIRAM_ENC_EXEMPT 预留 |
| 6 | PDM 不支持全双工 → 麦/功放必须分占 I2S0/I2S1 | 中 | 验证 I2S0-PDM-RX（16kHz）+ I2S1-STD-TX（48kHz）并发无冲突；顺带验证 `tune_rate` |
| 7 | TAS5805M/MA12040P 无现成 esp_codec_dev 驱动 | 中 | 拿功放 EVM（或手焊模块）接 devkit I2S1+I2C，先出正弦波再接 xiaozhi 播放链路；MA12040P 注意其 I2S 格式/采样率配置 |
| 8 | **ASRC 存疑**：start.md 称芯片有 ASRC，IDF v6.1 S31 文档无 ASRC 页（仅 tune_rate） | 中 | 查 S31 TRM/数据手册"ASRC"章节；若无，时钟架构按"Wi-Fi 时钟漂移用 tune_rate/软件重采样"设计 |
| 9 | xiaozhi S31 板型标记 `preview:true`，完整度未验证 | 中 | ESP32-S31-Korvo-1 刷 xiaozhi 官方 release 固件，全链路实测（唤醒词→云端对话→Opus 播放→音量/配网/OTA） |
| 10 | esp-adf v3.0 与 IDF v6 兼容未声明 | 低 | 不引入；若未来需要 ESP-GMF 媒体管线再评估 |
| 11 | 乐鑫官方 S31 云端 LLM 方案是否存在（本次检索受限） | 低 | 跟踪 espressif GitHub org 新仓、developer.espressif.com 博客；不影响采用 xiaozhi 参考 |
| 12 | 32MB PSRAM 模组选项存在性 | 中 | 查 ESP32-S31 模组系列 datasheet（官网模组页），影响 138 板型裁剪与 PSRAM 预算 |
| 13 | RISC-V 工具链具体版本（riscv32-esp-elf）未从文档页获取 | 低 | devkit 环境安装时 `idf.py --version` + `riscv32-esp-elf-gcc --version` 记录入仓库 README |

**固件先行验证清单（样机投板前全部通过）**：① IDF v6.1 + S31 devkit 基础构建/Wi-Fi/PSRAM；② esp-sr 唤醒（含内存实测）；③ QSPI AMOLED 点亮 + LVGL9 fps；④ PPA fill/blend + JPEG 硬解码 demo；⑤ I2S0 PDM 采麦 + I2S1 功放出音（含 TAS5805M/MA12040P 自研驱动）；⑥ xiaozhi 固件在 Korvo-1 全链路；⑦ 全部组合到同一工程做内存余量审计（heap 高水位 + PSRAM 用量）。
