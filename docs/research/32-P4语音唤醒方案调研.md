# P4 语音唤醒方案调研（2026-10-30；触发：唤醒词"你好墨墨"定制路径选型）

## 0. Kaleido 的约束（选型判据）

| 判据 | 要求 |
|---|---|
| 许可 | 开源可商用（repo 定位开源，禁专有 access-key） |
| 唤醒词 | 最终要"你好墨墨"（中文三音节），免费可定制 |
| 硬件 | ESP32-P4（RISC-V 双核 400MHz，32MB PSRAM，int 预算 ~200KB 级） |
| 前端 | 已有 16kHz mono 喂音管线（aio 环→feed 任务），方案须能吃裸 PCM |
| 误触/漏触 | 桌搭常开场景：日误触 ≤1，真人唤醒 ≥9/10（现行 WakeNet 实测 6/6） |

|---|---|---|---|---|---|

## 2. 关键可行性事实（本轮核实）

1. **TFLM 官方支持 P4**：espressif/esp-tflite-micro v1.4.1 + espressif/esp-nn v1.3.0
   均声明 ESP32-P4（RISC-V 优化内核）——microWakeWord 系模型的运行时
   底座现成，`idf.py add-dependency` 即用。
2. **microWakeWord 模型输入=裸 16k int16 PCM**（特征提取内嵌 tflite），
   与我们 aio 环→feed 管线零改造对接；输出=逐帧概率，阈值策略自定义
   （现行 0.35 经验可直接迁移参考）。
3. **中文训练路径已验证过同构先例**：mWW 训练集由 Piper 合成，社区
   法语词教程=换 Piper 音色即可；中文用 `zh_CN-huayan-medium`，声调
   特性需加强增广/掺真人样本（openWakeWord 自声微调流程可借用）。
4. **乐鑫免费词里没有"墨墨"近似词**，官方定制走商务流程（提交需求→
   语料采集→训练→交付），无公开报价与周期承诺——个人项目不友好。

## 3. 推荐路线（两阶段）

**阶段一（零风险，已就位）**：维持 WakeNet9"你好小智"。真人 6/6 实证，
不阻塞任何开发。

**阶段二（试点，预计 1-2 人日 + 一次 Colab 训练）**：
1. PC 侧：microwakeword.com 或 Colab all-in-one notebook，Piper 换
   `zh_CN-huayan-medium`，目标词"你好墨墨"（拼音 ni-hao-mo-mo，4 音节
   短语恰好是 KWS 甜区）；负样本用中文日常语料+现役设备自播 TTS 语料
   （防自唤醒：把 MiniMax 音色合成的提问/回答混入负集——正好复用
   pc-acoustic 的合成链）。
2. 板上：idf 依赖 esp-tflite-micro，新建 wakenet_mww.c 与 wn9 并存
   （编译开关二选一），吃同一 feed 管线，输出概率+阈值=现行 detect
   任务形状，FSM 无感。
3. 验收门禁（沿用现行口径）：真人 ≥9/10、'W' 回环机器音命中
   （mWW 对 TTS 音色应显著好于 wn9 的 2/10）、自唤醒泄漏 ≤1/10、
   夜 soak 误触 0、CPU 增量 ≤10%（P4 400MHz 应远低）。
4. 达标 → 切默认；不达标 → 保留 wn9 并把 mWW 试点结论归档。

## 4. 风险与未知

- mWW 对中文声调的泛化未经大规模验证（合成数据音色单一）——掺真人
  样本是关键保险；
- P4 上 esp-nn RISC-V 内核对该模型算子的覆盖度（个别算子回退参考
  实现会拖 CPU）——试点第一天先测纯推理耗时；
- nanowakeword 若半年内生态成熟，mWW 的模型可被同 runtime 替换
  （tflite 同谱系，切换成本低）。
