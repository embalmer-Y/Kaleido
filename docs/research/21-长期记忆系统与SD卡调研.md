| 版本 | 日期 | 作者 | 备注 |

> 调研问题：设备端长期记忆系统的存储/检索/备份技术方案，含"是否增加 SD 卡槽"的硬件权衡。
> 证据分级：**A** = 官方文档/官方源码级；**B** = 供应商页面/多源社区实测；**C** = 单源或设计推断。

## 结论先行（≤12 行）

1. **记忆系统本身不需要 SD 卡**。长期记忆是文本型数据：重度使用 1 年 ≈ 原文+摘要+索引 20–30MB，BOM 已含的 128MB SPI NAND（GD5F1GM7 类）绰绰有余；SD 的真实收益在**照片库扩容**（128MB≈400 张 vs 32GB≈10 万张）与**拔卡换机**体验，而非记忆。
2. **S31 SDMMC 引脚是硬约束（本项目新发现的代码级事实，A级）**：S31 的 SDMMC 不支持 GPIO Matrix 路由，**必须用 IO MUX 专用脚**——slot0 = GPIO20(D0)/21(D1)/22(D2)/23(D3)/24(CLK)/25(CMD)，slot1 = GPIO35–40。与 S3"任意映射"完全不同，选型不能照抄 S3 经验。
3. **引脚预算口径修正**：报告 01/15 的"余 4–5"未计 NAND 自身 SPI 4 脚（报告 15 只把它当存储落位未计入 GPIO 表）。修正后全配（36 + NAND 4 + 相机 13–14）余量仅 **0–2 脚**——**SDMMC 4-bit（+6 脚）在 v1 全配下不可行**；1-bit（+3 脚）勉强；SPI 模式与 NAND 共总线（+1 CS 脚）是加卡最低成本路径但仅 1–2MB/s。
4. **推荐方案 B：NAND 内建 + USB-C MSC / 局域网 / 可选云推送备份**（0 新增引脚），辅以 **A 的零成本预留**：PCB 上放 DNP 卡座焊盘 + GPIO20–25 在 G2 引脚表冻结时标为"存储保留段"。是否最终上卡的裁决点 = **G2 引脚表冻结**。
5. 记忆数据层推荐 **LittleFS + JSONL 分层存储 + 轻量索引**（掉电安全、可读、零堆碎片风险），不推荐设备端跑 SQLite（≈50KB+ 连续堆、FATFS 上掉电风险）；FlashDB 的 TSDB 模式作为索引层备选。
6. 检索架构：本地 tag/关键词/时间初筛 + **云端 embedding BYOK** 精排；embedding 向量可缓存回 NAND（float16，1 万条约 15MB），支持离线暴力扫描（~1s 内）。
7. 记忆分层参考 MemGPT/Letta（core/recall/archival 三层 + 自编辑 + 压缩）与 ChatGPT（saved memories + 历史引用、用户全程可见可删）；**xiaozhi 生态记忆在服务端**（mem0ai 等），Kaleido 设备端自存是差异化卖点，也必须自建备份。
8. 备份格式：`manifest + memory.jsonl + core.json + assets.tar`，seq 单调递增版本化、按 seq 合并导入，可选口令 PBKDF2→AES-256-GCM 整包加密（mbedTLS 内置）。
9. **USB-C MSC 是备份的关键抓手**：esp_tinyusb v3.0.0 已支持 S31 + MSC 设备模式 + esp_blockdev 后端（可挂 NAND FATFS 分区），与 UAC 复合；USB 口数据线已在规划内（耳机走 USB-C UAC），**零新增引脚**。注意：Korvo-1 的 Type-C 仅供电、无 OTG 数据口，MSC 无法在 Korvo-1 上验证，需 Mosaico 板或自板。

**文件系统裁决建议**：
- **记忆数据（高价值、小写入频繁）→ LittleFS**（掉电安全压倒一切；JSONL append+周期 sync 双保险）。
- **照片/备份导出/PC 可读区 → FATFS**（若加 SD 卡天然 FAT；若纯 NAND，用 spi_nand_flash_fatfs 划 FAT 分区兼作 USB MSC 暴露区）。
- **小配置/指针/密钥句柄 → NVS**。
- SQLite：**不推荐**（堆碎片+掉电风险换来的查询能力，在"时间+tag+关键词"检索模型下用不上；G2 若需求升级再议）。

## §3 引脚预算分析（核心矛盾量化）

### 3.1 S31 SDMMC 专用引脚铁律（新代码级事实，A级）

本地 ESP-IDF v6.1（commit gc55d13c6）源码证据：

- `components/esp_hal_sd/esp32s31/include/soc/sdmmc_pins.h`：
  - **SLOT_0：CLK=GPIO24、CMD=GPIO25、D0=GPIO20、D1=GPIO21、D2=GPIO22、D3=GPIO23**
  - **SLOT_1：CLK=GPIO39、CMD=GPIO40、D0=GPIO35、D1=GPIO36、D2=GPIO37、D3=GPIO38**
- `components/hal/esp32s31/include/hal/sdmmc_ll.h`：`SDMMC_LL_SLOT_SUPPORT_GPIO_MATRIX(SLOT_ID) = 0` → **S31 SDMMC 槽信号不可走 GPIO Matrix，只能用上述 IO MUX 专用脚**（对照：S3 的 `SOC_SDMMC_USE_GPIO_MATRIX=1` 可任意映射）。
- `sdmmc_default_configs.h`（S31 段）默认 slot0 即 GPIO20–25 —— **与 Korvo-1 板上"microSD 与 NAND 共享 GPIO20–25"完全吻合**（官方自己就把 SDMMC 放这组脚）。
- 其他能力：SDMMC 可 DMA 至 PSRAM（`SOC_SDMMC_PSRAM_DMA_CAPABLE=1`，利好照片管道）；UHS-I 需 1.8V 外部电源（`SOC_SDMMC_IO_UHS_POWER_EXTERNAL=1`），v1 不考虑。

**推论**：能否加 SD 卡 = "GPIO20–25（或 35–40）这整段 6 脚能否在引脚表冻结时空出来"，而不是"从剩余任意脚里凑"。

### 3.2 预算算术（修正口径）

| 项 | 脚数 | 备注 |
|---|---|---|
| 报告 01 基线外设 | 35–36 | docs/research/01 §6 |
| NAND SPI（本报告补计） | +4 | 标准 SPI（CS/CLK/DI/DO），Quad 需 +6；报告 15 未计入 |
| 相机 DVP（报告 15） | +13–14 | DVP 走 GPIO Matrix，**引脚位置可避开 20–25** |
| **小计** | **52–54 / 54** | **余 0–2**（报告 15"余 4–5"为未计 NAND 的乐观口径） |
| 可回收：JTAG GPIO54–57 | −（+4 可用） | 改用 USB 调试后回收（01 §6 注意③）；注意 54–57 在 ADC 区但可作 GPIO |
| 可回收：其他 | — | GPIO33/34（USB Serial/JTAG，建议保留烧录）；strapping 36/37/60/61 谨慎 |

### 3.3 加 SD 的三条路径与代价

| 路径 | 新增脚 | 速度 | 代价/风险 | 可行性 |
|---|---|---|---|---|
| A1：SDMMC **4-bit**（slot0 GPIO20–25） | 6 | 读写 8–20MB/s | 全配余量 0–2，**超支 4–6 脚**；须砍功能（如 SPI 相机化）或 DVP 分时复用 | **v1 不可行** |
| A2：SDMMC **1-bit**（GPIO20/24/25 三脚） | 3 | 读 4–5 写 2–4MB/s | 用尽余量；D1–D3 空置（卡内部上拉即可）；slot1 的 36/37 是 strapping 脚**优先避开**，统一用 slot0 | 勉强可行，无余量 |
| A3：SPI 模式，与 NAND **共 GP-SPI 总线**（+1 CS，+1 可选 CD） | 1–2 | 0.5–2MB/s | SPI 模式个别卡兼容性坑（IDF #16909）；与 NAND 分时 | 可行，最省脚但最慢 |
| A4：DVP 分时复用 GPIO20–25（拍照/存卡不同时） | 0 | 8–20MB/s | 每次切换重初始化外设+FAT 重挂载；固件复杂度高；**先例：Korvo-1 即 SD/NAND 共 20–25** | 记录为 hack，不作主选 |

**结论**：v1 全配形态下，"全速 SDMMC 4-bit"与引脚预算结构性冲突；加卡只剩 1-bit（挤占全部余量）或 SPI 共总线（慢）两条窄路。**引脚是全项目最稀缺资源（G2 后仍有测试点/新配件/新传感器未知需求），为"可拔插备份"这一单一收益花 3–6 脚，性价比低**——尤其 USB-C MSC 已能提供零引脚的备份出口。

### 4.2 设备端 schema（推荐：LittleFS + JSONL 分层）

分区规划（NAND 128MB，示例）：

```
nand:  [littlefs "memory" 64MB][fatfs "share" 32MB（USB MSC 暴露区/照片导出）][预留 32MB]
```

**层 1 core（≤256KB，`core.json` + NVS 指针）**：persona 块 + 用户事实块（上限 ~100 条），每条带置信度与时间戳。随每轮对话注入（token 预算见 4.4）。

**层 2 episodic（JSONL 追加，主存储）**：

```json
{"id":"ep_000123","seq":4521,"t":"2026-10-25T14:03+08:00","kind":"episode",
```

**层 3 raw（原文，90 天滚动）**：对话全文按日分文件，层 2 的 `src` 指回。

**索引（内存 + 持久化）**：tag 倒排 + 时间 B 树（TSDB 语义，可用 FlashDB TSDB 实现或自研 ≤500 行）+ 关键词集合（中文 bigram）。

写入路径：`会话结束 → 云端 LLM（BYOK）异步摘要+抽事实 → 设备 append JSONL（先写临时再原子 rename 或双缓冲 manifest）→ 闲时（充电/深夜）合并压缩 + 刷 embedding`。掉电策略：LittleFS COW + 每次 append 后 10s 内 fsync + manifest 双副本。

### 4.3 检索（RAG 最小形态，云端 embedding BYOK）

1. **初筛（本地，<50ms）**：时间衰减 × tag/关键词命中 × importance，取 top-20。
2. **精排（云端，BYOK）**：查询文本与候选（或全量摘要）送 embedding API 算相似度；或**本地向量缓存**：embedding 以 float16 存 NAND（768–1024 维 ≈ 1.5–2KB/条；1 万条 ≈ 15–20MB），查询向量云端算好后本地暴力余弦（SIMD 可用，含读 NAND 约 0.5–1.5s，1 万条规模可接受；更大规模退化为"仅初筛"）。
3. **注入**：core（≤300 tok）+ top-5 情节（≤400 tok）进 system prompt，总量预算 **≤800 tok**（LLM 上下文由云端承担，设备只管编排）。

### 4.4 遗忘与压缩

- **TTL 分层**：raw 90 天 → 自动摘要后删除；episode 永久（KB 级）；core LRU + 上限 + 用户管理界面（必做，对齐 ChatGPT"manage memory"）。
- **压缩**：闲时将同一 tag/同周的 episodes 合并为周记级摘要（LLM 完成），保留原始条目为 `archived`（可被"回忆更早的事"检索到，但不再进默认索引）。
- **"遗忘"即产品功能**：UI 提供按 tag/时间/单条删除；删除同步写 manifest（备份一致性）。

## §5 备份与迁移

### 5.1 通道对比（按推荐优先级）

| 通道 | 机制 | 新增硬件 | 用户体验 | 状态 |
|---|---|---|---|---|
| **USB-C MSC（主推）** | esp_tinyusb v3.0.0 MSC 设备模式，把 NAND 的 FATFS "share" 分区暴露为 U 盘（esp_blockdev 后端，多 LUN 可再挂导出镜像）；与 UAC 复合或模式切换 | **0**（USB_DP/DM 专用脚 + 数据线已在 UAC 规划内） | 插电脑即见 `/Kaleido/export/` 拖走备份/照片 | S31 支持已确认【A】；**Korvo-1 无 OTG 数据口，验证需 Mosaico 板/自板** |
| **局域网 HTTP(S)（主推）** | 设备起 Wi-Fi 服务，网页浏览/检索/删除记忆 + 一键下载备份包；同网段零依赖 | 0 | 手机浏览器即可完成（无 PC 线） | 纯固件 |
| **云推送（可选）** | 用户自配 WebDAV/S3 兼容端点（BYOK 精神），夜间按 seq 水位增量推送 | 0 | 自动异地容灾；丢机不丢记忆 | 纯固件 |
| **microSD 整卡（若走方案 A）** | 备份直写卡 FAT 目录；换机=拔卡插入新机导入 | 卡座+3–6 脚 | 最直觉 | 依赖 §3 裁决 |

### 5.2 备份包格式（所有通道统一）

```
kaleido-backup-20261025-<seq4521>.tar[.enc]
 ├─ manifest.json   # device_id, schema_ver, last_seq, 条目数, sha256, 加密参数
 ├─ core.json
 ├─ memory.jsonl    # 全量或增量（since_seq）
 └─ assets/         # 关联照片/事件的引用文件（可选段）
```

- **版本化**：全局 `seq` 单调递增（NVS 保存水位）；本地保留最近 N=3 代全量 + 每日增量。
- **导入/换机**：新设备扫描备份 → 按 `(id, seq)` 合并，seq 高者胜；manifest 校验 sha256。
- **加密（可选）**：用户口令 → PBKDF2-HMAC-SHA256（≥100k 迭代）→ AES-256-GCM 整包（mbedTLS，IDF 内置，无新增依赖）；口令不落设备。默认不加密（开源设备+本地优先），设置里开启。

## §6 候选方案与推荐

| 维度 | **方案 A：加 microSD 卡槽** | **方案 B：NAND 内建 + USB/网络备份（推荐）** |
|---|---|---|
| 硬件改动 | 卡座+上拉+退耦 ≈ <¥3；**+3 脚（1-bit）或 +6 脚（4-bit）或 +1 脚（SPI 共总线）**；结构侧开孔（~15×17mm）；slot0 GPIO20–25 必须整段保留 | **0 新增**；可选 NAND 升 256MB（+¥2–3）缓解照片容量 |
| 固件工作量 | 低（sdmmc/fatfs/sdspi 全现成；Korvo-1 板载 microSD 可实测） | 中（LittleFS 分层 + MSC + LAN 页 + 云推送 ~3 个模块；均可并行开发） |
| 用户体验 | 拔卡备份/换机最优；32GB 照片自由；PC 直读 | 插 USB 拖文件/手机网页备份；换机走导出导入（5 分钟级）；照片受 128/256MB 限（400–800 张） |
| 风险 | FAT 掉电脏、山寨卡方差、**挤占全项目最稀缺引脚**（G2 后未知需求无缓冲）、slot1 strapping 坑 | MSC×UAC 复合设备调试；"设备丢失=记忆丢失"（靠云推送缓解）；照片容量天花板 |
| 与记忆系统关系 | 记忆本身不需要它（20–30MB/年级） | 完全满足记忆存储+备份+迁移 |

**推荐：方案 B 为 v1 基线，同时给 A 留零成本后悔药。**

1. v1 **不焊卡座**：记忆与备份需求由 NAND + USB-C MSC + LAN（+可选云推送）完整满足，引脚余量留给 G2 后的未知需求。
2. **PCB 零成本预留**：GPIO20–25 在 G2 引脚表冻结时标为"**存储保留段**"（DNP 卡座 footprint + 每脚 0Ω 串阻焊盘 + 4 上拉位），相机 DVP 等大块外设避开该段。若 G2 后确认"照片日记/存档"为高优产品方向，v1.1 贴卡座升级 SDMMC 1-bit（4-bit 需再评估回收 JTAG 脚），固件仅加 sdmmc 挂载。
3. 决策点：**G2 引脚表冻结时裁决保留段去留**（若届时连 6 脚保留都挤不出，则 SD 从产品路线图移除，仅存 USB/网络备份）。

一句话：**记忆系统落在 NAND 上的分层 JSONL + 云端 embedding 检索；备份走 USB-C MSC/局域网；SD 卡不进 v1 BOM，但在 GPIO20–25 留 DNP 预留。**

## §7 风险与第 2 轮建议

| # | 风险/待验证 | 等级 | 验证手段（建议入 V 清单） |
|---|---|---|---|
| R1 | **引脚口径修正未获确认**（NAND 4 脚是否已在他处计入） | 高 | G2 引脚表冻结时逐块核对（V-29） |
| R2 | S31 在 IDF v6.1 为 preview，sdmmc/spi_nand/BDL 栈成熟度 | 高 | Korvo-1（板载 microSD 4-bit + NAND 焊盘）实测 1-bit 模式吞吐与掉电重挂载（V-31）；spi_nand_flash+dhara FTL 吞吐/掉电（V-27，需贴 NAND 料） |
| R3 | esp_tinyusb MSC×UAC 复合在 S31 无人验证；Korvo-1 无 OTG 数据口 | 高 | Mosaico 板或首块自板验证 MSC 挂 NAND FAT 分区 + UAC 并存（V-28） |
| R4 | esp-claw 记忆子系统仅 S3，S31 移植工作量未知 | 中 | 源码审计其存储依赖（文件系统/NVS/内存）→ 输出移植清单（V-30） |
| R5 | FATFS 掉电损坏（若走 A 方案或 share 分区直写） | 中 | 导出走"临时文件+rename"；share 分区损坏可重建（数据在 LittleFS 主存储） |
| R6 | 云端 embedding 供应商锁定/停服 | 中 | 只存原文+tag，embedding 可随时重算；schema 预留 emb_model 字段 |
| R7 | 山寨 SD 卡性能/寿命方差（若上 A） | 中 | 仅推荐工业卡；固件启动时测速告警 |
| R8 | 记忆数据隐私（设备被盗/转卖） | 中 | 默认本地+可选整库 AES 加密；"恢复出厂"物理擦除 NAND |

**给第 2 轮（G2）的输入**：① §6 决策建议与 §3 引脚保留段写入引脚表冻结议程；② V-27～V-31 并入验证计划（V-31/Korvo-1 可立即做，零采购）；③ 记忆分层 schema（§4.2）与备份包格式（§5.2）作为"灵魂"架构设计文档（kaleido-claw-架构后续版）的存储层输入。
