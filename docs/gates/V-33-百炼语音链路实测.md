## §3 ASR 数据（paraformer-realtime-v2，回环：TTS pcm@16k → 100ms 分片喂入）

- 全链：8.5s 音频 → 定稿 `今天天气真不错。我们去公园走走吧。哎，对了，你上次说的那个项目后来进展怎么样了？`
- 时间线：task-started **48ms**；首 partial（"今"）**646ms**（含喂入节奏 ~600ms，实际 ASR 出字 ≈50-100ms/chunk）；最后 chunk→task-finished **461ms**（尾句定稿，含 200ms finish 延迟）。
- 事件结构（固件解析依据）：`payload.output.sentence.{text, sentence_end, words[]}`；**定稿标志 = sentence_end:true**（不是 output.type）；partial 持续覆盖同 sentence_id 文本。
- 回环伪影：TTS 说"对了"、ASR 听成"哎，对了"（合成音听写伪影，非链路错误；真机麦克风链路另测）。

## §4 复刻全流程（voice-enrollment，旧域名 HTTP）

1. `create_voice`（POST customization，base64 wav 16k/8.5s，target_model=cosyvoice-v3-flash，prefix=kaleido）：**200，1,682ms**，返回 `voice_id = cosyvoice-v3-flash-kaleido-<16hex>`（格式 `{target_model}-{prefix}-{id}` 与文档一致）。
2. 轮询 `query_voice`：DEPLOYING → **OK（第二次轮询，≈5-8s）**。
3. 克隆音色合成：见 §2 末行 ✅。
4. `list_voice`：200（该账号已有 19 个音色，上限 1000，无压力）。
5. `delete_voice`：200（测试音色已删；复现只需重跑 clone_probe.py，1.7s+5s）。
- 请求体要点（固件实现依据）：`{"model":"voice-enrollment","input":{"action":...,"target_model":...,"prefix":≤10 位字母数字,"audio":"data:audio/wav;base64,..."}}`；音频支持 URL 或 base64 Data URI；可选 language_hints/max_prompt_audio_length(3-30s)。

## §6 固件实现要点（M1.5 输入）

1. **协议**：WS 二进制/文本帧双通道；TTS=run/continue/finish-task + 二进制音频帧；ASR=同 task 协议反向（100ms/3200B pcm 分片上行，sentence_end 聚合定稿）。事件 JSON 结构见 §2/§3。
2. **断句策略**：LLM SSE delta → 攒到句读（，。？！）即 continue-task——服务端自动分句意味着**首句即播**天然成立，无需设备端 NLU。
3. **打断（barge-in）**：唤醒触发 → 不发 finish-task 直接关 WS（服务端按 task 超时自清）；或发 task-cancel（待查文档，M1.5 验证）。
4. **克隆链路**（.kpersona voice.enrollment）：录 10-20s → base64 → create_voice → 轮询 OK → voice_id 回填；fallback 预置音色 longanyang（已验证）。
5. **遗留**：新域名迁移跟踪（阿里公告）；qwen-tts-realtime 模型名灰度问题二期复查。
