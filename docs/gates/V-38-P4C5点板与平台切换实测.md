# V-38 · P4C5 点板与平台切换实测（B-1/B-2 门禁）

日期：2026-10-25 ｜ 板：鱼鹰光电 osptek P4C5 10.1" 套件（ESP32-P4 v3.2 + C5HF4）
结论：**全绿**——点板冒烟 PASS（B-1）、主固件 esp32p4 重定向 + M0 上板跑通（B-2）。
背景：W-7 判死 Korvo-1 → D-8 平台切换（26 号调研）。

## 1. 环境与工具链

- ESP-IDF v6.1-1-gc55d13c6（同 S31 时期，零更换；esp32p4/esp32c5 均为 stable target）
- 调试口 CH343P `/dev/ttyACM0`；烧写 **`--no-stub` ROM 模式 @230400**（stub 在 921600/460800/230400 全部无响应——CH343P 通路问题，与 S31 那块同症状不同根因）
- 复位：RTS 直拉无效；`idf.py flash` / `esptool --after hard-reset` 的组合复位序列有效

## 2. B-1 点板冒烟（p4-bringup，提交 2f4b4b1b）

启动横幅（实测摘录）：

```
P4-BRINGUP,PASS-START
idf=v6.1-1-gc55d13c6 rev=v3.2 cores=2
flash=16MB psram=32MB
mac=e8:f6:0a:e9:66:c3
heap int=578KB psram=32765KB largest_psram=32256KB
part nvs 0x011000+0x6000 / phy 0x017000 / factory 0x020000+0x800000 / storage 0x820000+0x700000
P4-BRINGUP,PASS-END
```

- PSRAM：32MB HEX@200MHz（hex_psram 厂商 AP 0x0d、X16、Burst 2048B），最大连续块 32,256KB
- flash：JEDEC 0x68 = **Boya**，16MB，出厂固件内容可正常执行（对比 W-7 板的假读）
- 出厂固件备份：`kaleido-fw/tools/hil/p4-bringup/backup/`（factory_app_backup.bin 1MB + partition_table_backup.bin，已 gitignore）

## 3. B-2 主固件切换（提交 e4362d67）

三轮排障实录（都有复现证据）：

1. **bootloader 超限**：XIP-on-PSRAM 使 bootloader 达 0x6140 > 0x8000 表偏移限额 0x6000 → 分区表偏移改 0x10000（恰为出厂布局）。
2. **Boya flash 专用驱动（根因）**：通用驱动 + QIO 启动到 `sleep_gpio` 初始化后 **Guru Meditation: Store access fault**（寄存器现场已存档）；`CONFIG_SPI_FLASH_SUPPORT_BOYA_FLASH_CHIP=y` 后 QIO@80MHz 正常。出厂固件本身就带 QIO（其构建启用了 Boya 支持）。
3. **XIP-on-PSRAM 挂死（未结案）**：通用驱动时期 XIP 开启会在 heap 池初始化后完全静默（无 panic 无 WDT）。Boya 驱动修好后**未复测** → 疑似同根因，**V-37 复测后定论**（P4 池 32MB，XIP 只影响启动镜像搬运 ~固件尺寸，收益/代价与 S31 完全不同，须重测）。

最终上板输出（M0 骨架）：

```

kapp: registered com.kaleido.clock v1.0.0 (perm=0x01 src=0)
kapp: registered com.kaleido.settings v1.0.0 (perm=0x81 src=0)
kaleido: [app] com.kaleido.clock: 0 → 2
kaleido: [app] com.kaleido.settings: 0 → 2
kaleido: registry: 2 app(s) — M0 skeleton OK
```

固件 205KB / factory 8MB 分区（98% 余量）。
