# Kaleido 内存占用清单（convo-stage 合并版实测）

> 2026-10-26 · V-45 战场快照 · 口径：ESP32-P4（512KB 静态 DIRAM + 32MB HEX PSRAM@200MHz）
> 数据来源标注：**[实测]** = 串口 VL,MEM / idf size / map 解析；**[推导]** = 由分配代码计算。
> 目的：debug 导航图。每次大改后用 §7 的命令重测一列即可对比。

---

## 1. 总览

| 资源 | 总量 | 静态占用 | 开机剩余（64B 缓存行） | 备注 |
|---|---|---|---|---|
| 内部 DRAM（DIRAM） | 524,288 B | 378,730 B（72.2%）[实测] | **101 KB** [实测] | 其中 .bss 283,624 + .data 25,186 + DIRAM .text 69,920 |
| PSRAM | 32 MB | 0 B（ext_ram.bss 空） | **32,676 KB** [实测] | 静态段空置，大头全部运行期分配 |
| Flash（app 分区 8MB） | 8 MB | 3,086,914 B | 余 5.0 MB [实测] | .text 2,113,650 + .rodata 972,580（模型在独立分区 @0xF20000） |

**关键结论**：内部 RAM 的压力不在静态段本身（72% 看似健康），而在
**开机 → 运行的坍缩速度**：101 KB → 起显示/WiFi/wakenet 后仅剩 ~46 KB，
而 TTS announce 的第二路 TLS 需要几十 KB 级内部缓冲 → 'W' 硬锁死（V-45 第二阻断）。

## 3. PSRAM 运行期布局（开机 → pre-wifi 台阶拆解 [实测+推导]）

| 消费者 | 字节 [推导] | 说明 |
|---|---|---|
| DPI 双帧缓冲 | 2 × 800×1280×2 = **4,096 KB** | RGB565 整屏 ×2（防撕裂轮换） |
| ~~LVGL 旋转缓冲~~ | ~~2,048 KB~~ | `sw_rotate=true` 代价；**已修复回收** |
| ~~舞台三缓冲(ARGB)~~ | ~~1,268 KB~~ | thorvg 版已退役（V-45R） |
| 表情画布(RGB565) | **211 KB** | esp_emote_gfx flush 直写 lv_canvas |
| 'a' 探针 capbuf（运行期） | 31 KB | 已是运行期分配 |

## 5. 运行时内部 RAM 台阶（关键标尺）

| 时刻 | 内部剩余 [实测] | 事件 |

> 128B 行回退尝试（抬 185 KB）已实证不可行：`sleep_clock_icg` 启动分配失败 0x101
> bootloop（fix4/fix5 日志）。64B 行是 #219 修的既定代价，内部余量只能从别处赚。

## 7. 复测方法（每次大改后一列）

```bash
cd tools/hil/convo-stage
idf.py size                                   # 总量
idf.py size-components                        # 按组件
python3 - <<'EOF'                             # >512B 静态大符号扫描
import re, collections
L=re.compile(r'^\s*([\.\w][^\s]*)\s+(0x[0-9a-fA-F]+)\s+(0x[0-9a-fA-F]+)\s+(\S+)$')
S=collections.Counter()
for ln in open('build/convo_stage.map',errors='ignore'):
    m=L.match(ln)
    if m and m.group(1).startswith(('.bss','.data')) and int(m.group(3),16)>=512 \
       and 0x4ff00000<=int(m.group(2),16)<0x50000000:
        S[f"{m.group(4).split('(')[-1].rstrip(')').replace('.obj','.o')} {m.group(3)}"]+=int(m.group(3),16)
[print(f"{v:>9,} {k}") for k,v in sorted(S.items(),key=lambda x:-x[1])[:20]]
EOF
# 运行时台阶：串口抓 VL,MEM,boot / pre-wifi；新固件 STAT 心跳已内联 FB 采样与
# ~30s 一次 VL,HEAP,OK/CORRUPT 巡检（V-45 频闪取证仪表）
```

## 8. LVGL"官方方案"对比（回答：降标准能否省内存）

我们**已经在官方推荐方案上**：esp_lvgl_port 2.7.2 + LVGL 9.4.0，
DSI `direct_mode + avoid_tearing + 双 DPI fb + RGB565 + SW 单绘制单元`
——与 esp-idf P4 官方 DSI 示例同构；角色合成路径与官方 `esp_lv_lottie_player`
同款（thorvg→ARGB8888→lv_canvas）。显示全家占用：内部 RAM ≈ LVGL 静态 0.08 KB +
port 上下文 + **16 KB 任务栈** + DPI 描述符（合计 ~20 KB 量级），其余全在 PSRAM。

| "降级"选项 | 省 | 代价 | 判定 |
|---|---|---|---|
| 关 avoid_tearing 单 fb | PSRAM 2 MB | 撕裂（舞台动画场景不可接受） | 否 |
| partial 模式小缓冲 | PSRAM（fb→1/10 屏） | 全屏重绘×多段 flush，CPU 涨、仍撕裂 | 否 |
| 关 sw_rotate | **PSRAM 2 MB** | 无（本形态不旋转） | ✅ 本次已做 |
| 降色深 RGB565→I1/A8 | 带宽 | 面板 RGB565 已是硬件下限 | 不可行 |

**结论**：显示链不是内部 RAM 的瓶颈；内部 RAM 大头是 64B 缓存行价（185 KB，
#219 修的既定代价）+ 探针静态缓冲（160 KB，已修）+ WiFi/hosted/TLS/wakenet
运行期。下一步若仍缺内部余量，方向是 hosted 头补丁与 TTS 路径的分配审计，
不是动 LVGL。
