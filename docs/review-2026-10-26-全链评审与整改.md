## §1 总评

**整改前：可用但带伤（阻断级缺陷 3、崩溃级 7、严重风险 10）；整改后：全部

缺陷计数（四路合并去重）：**崩溃级 7 / 严重风险 10 / 清理项 9 / 文档失实
10 / 注释缺口 6**。整改 5 个提交全部落地，逐项映射见 §3。

## §4 架构演进（分层与可扩展性）

整改后的语音链分层（M2 可直接复用）：

```
components/kaleido_speech          ← provider 层（持久代码）
  ├─ ks_asr_*   (sp_dashscope.c)     DashScope WS ASR
  ├─ ks_tts_*   (sp_minimax.c |      TTS provider 按 Kconfig 二选一，
  │              sp_dashscope.c)     对称 open/feed/close
  └─ ks_llm_*   (sp_llm.c)           流式 chat/completions + JWT→URL 工具
tools/hil/voice-loop-p4            ← HIL（试验编排，瘦）
  ├─ 子句泵（常驻服务：队列+feeder，reset/stop 生命周期）
  ├─ 播放通路（s_pb StreamBuffer → play_task，扬声器唯一写者）
  └─ wakenet_test（唤醒引擎，待 M2 状态机收编）
```

关键动作：**llm_stream.c 从 HIL 升格为组件 sp_llm.c**（原实现零 HIL 依赖，
迁移近乎原样）；**GroupID/JWT 细节退出公开 API**（ks_llm_minimax_url 一步
到位）；**分句泵从按轮创建改为 boot 常驻服务**——生命周期缺陷类（幽灵
消费者/漏哨兵/双消费者）被结构性地消灭，而不是逐路径打补丁。

显示侧：bg_jpeg 从"自带 EMBED 资产的休眠模块"改为"参数化能力"（壁纸场景
再入资产），lottie_bench 归档出编译，舞台邮箱语义成文（文件头两条不变量）。

## §7 建议与遗留

按优先级：

1. **M2 状态机开工前的两个前置**（本次已铺好地基）：采音/播放所有权仲裁
   （单一采音任务 + 一切声音经 s_pb 汇聚）与显式 `idle→listening→round→
   re-listen` 状态枚举收编 wakenet 双任务。
2. **MiniMax key 走 NVS**（与 ASR key 同为 BYOK 语义；现在 CONFIG_KS_MM_KEY
   会把 JWT 烧进 flash 镜像，开源前必须换路线）。
3. **provider 会话互斥锁**替代纯契约文档（第二只 provider 或运行时切换落地时）。
4. **自动化回归**：'t' 内置轮已是无人值守端到端，建议接 serial→判分脚本
   进 CI 占位（coding-style 的 CI 承诺同样待兑现）。
5. 上游 issue 候选照旧（esp_hosted SDIO 断言、thorvg meson 引号、
   esp_lvgl_port 文档配对说明）；GitHub 旧 token 撤销提醒仍有效。
6. 冗余清查的边界决定：voice-loop（S3 祖先）按门禁证据保留冻结；内外仓
   docs/ 分属两库（constraints §10.1 说门禁应在外仓）——G6 开源前统一。
