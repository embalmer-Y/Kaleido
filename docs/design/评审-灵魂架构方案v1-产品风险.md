## §1 总评

**有条件通过（产品/风险席口径：定稿对齐前必须补齐 2 条阻断 + 5 条严重）。**

架构组件裁决与选型证据链扎实（技术席已核实），防骚扰八条、离线降级（Moxie 教训）、"用户全程可见可删可关"隐私原则、首次响应诚实口径 1.5-2.5s、复刻 fallback_voice_id 必填等设计判断**值得肯定**。但从产品交付视角，本方案是一份**"引擎设计书"而非"产品定义书"**：它完整回答了"灵魂如何运作"，几乎没有回答——

1. **用户第一天如何得到灵魂**：出厂默认两大功能（AI 对话、Claw 写 App）与灵魂六项能力**全部**依赖至少 2 把 API key，方案对无 key 开箱、配 key 引导、欠费/失效/超额状态零着墨（阻断）；
2. **灵魂对用户承担什么责任**：主动开口的情感内容生成、声音复刻、90 天对话原文、常开麦克风——方案对国内生成式 AI / 深度合成 / 未成年人保护零覆盖（阻断）；
3. **灵魂与"平台型"产品定义的关系**：出厂角色常驻全屏舞台实质推翻了已裁决的 Q-1"主屏 = App 网格"，未走决策登记（严重）。

多数缺口不是"实现细节后补"型：麦克风隐私硬件、角色/产品命名、Q-1 主屏冲突都有 **G2 冻结前的时间硬点**。

- **阻断 2 条；严重 5 条；一般 12 条；建议 4 条。**

## §2 产品 / 体验问题（按严重度）

| # | 严重度 | 问题 | 证据与说明 |
|---|---|---|---|
| P1 | **阻断** | **开箱体验（OOBE）整体缺失：无 key 用户拿到设备的第一天是"呼吸摆件 + 设置页"** | start.md Q-4 裁决"无 key 时仅离线能力可用（唤醒+本地命令）"——但灵魂六项（对话/角色语音/情感回应/点火内容/访谈创建/记忆摘要）全部需要 LLM key + 百炼 key（ASR/TTS/复刻）。方案 §6 M1.5 依赖"用户提供百炼 key"，却没有任何一节定义：①开箱引导流程（用户需注册阿里云账号 + 一家 LLM 服务商，拿 2 把 key，估 10-20 分钟，对非开发者用户是真实门槛）；②"本地命令"具体集合；③key 失效/欠费/超额三态的设备端 UX（当前设计里这些场景=设备沉默，用户无从知道为什么）；④新用户免费额度/体验策略（19 号未核验百炼新用户额度，属待查）。对标 Mosaico 的"开箱即用"差距最大处恰在此。 |
| P2 | **严重** | **定位漂移未裁决：角色常驻全屏舞台推翻 Q-1"主屏=App 网格"既定裁决，未走决策登记** | 总体架构概览 §6 Q-1（2026-10-24 负责人裁决）："KShell 主屏 = App 网格；出厂内置仅最小集；产品叙事以可定制为核心"。25 号 §4.3 与方案 §2/§0.6：kaleido_express 为 KShell 原生舞台，"默认全屏 460×460、App 前台时角标"——**主屏事实上变成了角色**。这是产品身份从"平台"向"陪伴玩具"的实质移动（负责人的"灵魂"指示本身构成授权，但 Q-1 是已裁决项，按 constraints §10.4 变更纪律应显式修订 start.md/概览并登记，方案只在文末说"裁决后同步修订"，未把"主屏归属"列为待裁决项）。另外"角色可关闭、退回 App 网格"仅见于 25 号落地形态一句，方案正文未写入——**建议作为 D-7 新增决策：出厂默认形态 = 角色舞台 / App 网格 + 角色角标，二选一**。 |
| P3 | **严重** | **BYOK 全链门槛与月成本口径失真：35-50 元/月漏掉 LLM 主成本，无分层与降级策略** | 19 号 §5 组合 A 口径 = ASR 5h（~4 元）+ TTS 30 万字符（30-45 元），**不含 LLM 对话 token 费**（BYOK 用户所选模型决定，月 2-70 元不等，重度+海外旗舰模型可上 $10/月）、不含 embedding（<$0.2 可忽略）与点火裁决（$0.04-2.5/月，22 号 §4.1）。方案 §0.2 直接沿用"1-1.5 元/万字符最低档"话术，从未给出用户视角的**全口径月账单**。用户要填的 key 至少 2 把（LLM + 百炼），方案全文未明示这一数字。自托管路径画像（有 6GB+ GPU NAS 的极客，19 号 §3.3）成立但小众，"社区自助不进 SLA"的处理正确。缺：轻/中/重度三档月成本表、设置内用量可视化、配额耗尽/欠费降级（如自动停点火、TTS 降级预置音色并屏显提示）。 |
| P4 | 一般 | 记忆跨角色默认共享（O-1）的隐私心智冲击未设计披露 | 25 号 §3.4：episodic/用户事实全局共享为默认，方案 D-7-6 建议照单采纳。"新角色知道我和旧角色的全部经历"对用户是显著的意外（creepy factor）。建议：默认共享保留，但**首次创建第二个角色时显著告知 + per-persona 过滤开关放在创建流程里**而非埋在设置深处。 |
| P5 | 一般 | .kpersona 导出包含 interview.md（访谈原文）与 overrides，导出即泄露用户访谈内容 | 25 号 §2.2 包结构含 `card/interview.md`（"用户可见可删"）；W7 网页工坊一期即有导入导出（§6.1），O-5 二期社区分享 = 包互传。访谈记录是用户与设备的私人对话，**分享/导出必须走白名单字段剥离**（persona.json + assets + LICENSE，剔除 interview.md/overrides/情感快照）。当前设计未设剥离规则。 |
| P6 | 一般 | 断网体验有降级架构（确认，正面），但无用户可见规格 | 方案 §0.4"决策内核本地离线可用"、25 号 `EXP_SYS_OFFLINE` 枚举存在；但"离线时设备表现"（屏显话术、可说哪 5 条本地模板、点火是否完全静默）无规格。离线是高频场景（Wi-Fi 闪断），值得一页状态机说明。 |
| P7 | 建议 | 点火默认口径统一 + 新机首周"克制模式" | 22 号 §5.1 默认日上限 8 次；方案 §0.4 写"4-8"、§8 写"保守默认（日 4 次）"——建议全文统一为"默认 4，用户 0-20 可调"。另建议新机前 3 天主动度自动减半（首因效应：第一周就烦=永久关掉，22 号 §3.5"错误时机的打断比沉默伤害大"）。 |

**正面确认**（不计问题）：访谈式创建三路径完整（25 号 §3）；音色复刻失败保底预置音色；角色切换 <2s 无重启规格明确；memory 可视可删可关对齐 ChatGPT 范式；延迟口径诚实不吹 1.5s。

## §3 隐私 / 安全 / 合规缺口

| # | 严重度 | 缺口 | 证据与说明 |
|---|---|---|---|
| H1 | **阻断** | **内容安全与国内合规立场零覆盖：生成式 AI / 深度合成 / 未成年人三线全空白** | 方案 §4 关键纪律列了防骚扰八条、ethics_latched、private 级不进云——**全部是行为纪律，无一条内容纪律**。现实约束：①设备**主动开口**生成情感陪伴内容（点火），经 BYOK 云 LLM 产出后由扬声器播出——国内云厂商（百炼等）自带内容审核（利好），但 BYOK 允许用户填任何 OpenAI 兼容端点（含无审核端点），不当内容会由设备"说出声"，项目声誉风险直接落在 Kaleido 头上；②**声音复刻属深度合成**（《互联网信息服务深度合成管理规定》将语音合成/克隆列入），显著标识与同意要求落在产品 UX 上，19 号 R5/25 号 §3.2 仅有同意声明雏形，无显著标识与复刻他人声音的法律提示设计；③**未成年人**：可爱角色 + 情感陪伴天然吸引未成年人，方案无年龄口径、无家长指引、无防沉迷姿态（Moxie 本身就是儿童产品）。需要新增"合规与内容安全"一节 + 一条 D-7 决策：项目立场建议明确为"**开源工具、无默认云服务、无账号体系、纯 BYOK**（服务提供者责任归云厂商）"，同时做三件产品级兜底：TTS 前本地敏感内容门（拦截→模板兜底）、复刻显著标识文案、说明书年龄建议。这些不是上线前外挂能补的（影响 prompt 组装、点火模板库、固件组件）。 |
| H2 | **严重** | **首次开机隐私声明与数据出云清单缺失** | 设备常态：麦克风常开（WakeNet 唤醒监听）、摄像头（有物理拨片，正面）、IMU、对话原文 90 天滚动（21 号 §4.4）、点火日志、云 embedding 精排（查询文本与候选摘要出云，21 号 §4.3——**注意首刷会把全量记忆摘要批量送云**）。方案只有一句"用户全程可见可删可关（隐私卖点）"。缺：首次开机一页式告知（听什么/存什么/送什么/给谁）+ 逐项开关（记忆上云可关=退化为本地初筛，21 号已有降级路径但未与同意流绑定）+ 云 embedding 首刷的显式同意。22 号 §6.2"一直在听？"风险已识别但方案未承接为产品动作。 |
| H3 | **严重** | **麦克风无硬件静音/指示通路，且必须在 G2 引脚表冻结前裁决** | 摄像头有物理遮挡拨片（总体架构概览 §3），麦克风什么都不带。"一直听着"的感知风险（22 号 R）最小解是硬件佐证：物理静音开关或麦克风 LED。引脚余量修正后仅 0-2 脚（21 号 §3.2）——**这是 D-7 清单遗漏的"其实必须现在决定"项**：不做则 v1 无硬件隐私通路，做则要挤占最后的引脚余量。 |
| H4 | **严重** | **备份默认不加密 + USB MSC 即插即读 + 90 天对话原文：与"隐私卖点"自相矛盾** | 21 号 §5.2"默认不加密（开源设备+本地优先），设置里开启"；备份包落在 FATFS share 分区 = USB MSC 暴露区（§1.2/§5.1），插电脑即见 `/Kaleido/export/`。设备丢失/转卖/桌搭场景（办公室/宿舍公共桌面）下，一根数据线拖走 90 天对话全文 + 点火日志 + 用户事实。21 号 R8 仅评"中"。建议：备份默认口令加密（首次导出强制设置或强提示二选一），"恢复出厂"物理擦 NAND 已有（好）。 |
| H5 | 一般 | 数据出境说明缺失 | 用户自选境外 LLM/embedding 端点时，对话文本与记忆摘要出境。BYOK 下属用户自担，但隐私声明应有一句知情说明（不阻止、要告知）。 |
| H6 | 一般 | ethics_latched 触发标准无归属：阈值是谁定的、闩锁后用户看到什么 | 18 号 §5.2：Galatea 原阈在其动力学下**构造性不可达**，Kaleido 输入映射下需重推导（技术席 C12 已列）。产品侧增量问题：①重推导后的阈值=产品价值观判断（多严重的持续负面才触发保护），应列为负责人裁决而非默认参数；②闩锁行为规格（22 号 §5.6"只允许预置安抚模板+提示用户"）未定义提示形态——无手机推送通道，屏显？语音？持续多久？谁来解锁？ |
| H7 | 一般 | 复刻"他人声音"仅自我声明兜底 | 25 号 §3.2 同意声明是"复刻自己的声音"流程；复刻他人（家人/名人）声音的侵权风险（深度合成规定+民法典声音权益）只有一句声明文案。建议：朗读**服务端随机指定文本**（防录好的他人素材直接回放）+ 文案明示法律责任。 |

## §7 评审结论

**有条件通过。** 六个子系统的技术裁决（组合 C 语音链路、L05 情感内核、点火 A→B、三层表达、NAND 记忆、MCP 感官复用）在产品层面均成立且差异化清晰，防骚扰八条与离线降级是同类产品少见的成熟设计。但方案当前把"灵魂"当作引擎设计得很完整，**没有回答"用户如何安全地拥有这个灵魂"**：

- 2 条阻断：**OOBE 缺失**（无 key 首日体验未定义，出厂默认功能 100% 依赖双 key 配置成功）与**合规缺位**（生成式 AI 内容安全/深度合成标识/未成年人零覆盖，且影响固件与 prompt 设计，非外挂可补）；
- 5 条严重：Q-1 主屏裁决被无声推翻、BYOK 成本口径漏 LLM 主成本、首次开机隐私声明与 embedding 首刷同意缺失、麦克风无硬件隐私通路（G2 引脚冻结前必须裁决）、备份默认不加密与"隐私卖点"自相矛盾。

上述多数问题有 **G2 冻结（引脚表）/ M2.1（命名、烧只读分区）的时间硬点**，应在方案定稿提交负责人裁决前完成 §6 的 P0 四项。完成后，本席对整体产品方向（"平台底座 + 出厂灵魂 + BYOK"）无保留意见。
