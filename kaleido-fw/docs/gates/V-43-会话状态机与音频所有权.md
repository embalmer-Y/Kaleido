# V-43 — 会话状态机 + 音频所有权仲裁（M2 语音主体）

日期：2026-10-26。结论先行：**通过**。免按键闭环 10/10 轮 rc=0、零
panic、内存平直；菜单轮回归绿。声学唤醒在本次验证窗口为 0/10——
环境噪声所致（见 §3），轮机制由合成唤醒兜底验证，声学检出另列。

## 落地

- **convo_fsm.c**：显式状态机 `OFF→IDLE→LISTENING→THINKING→SPEAKING
  →IDLE`；常驻 convo_task 等唤醒事件驱动整轮；VAD-lite 采音窗
  （3-12s，底噪自适应阈值，说话后 1.2s 静音提前截断）；每轮
  `VL,CONVO,ROUND` 遥测含 rc/说话时长/ASR 字节数/双堆余量。
- **clause_pump.c**：子句泵从 voice_loop_main 抽成模块（reset/attach/
  stop/detach 生命周期），菜单轮与 FSM 共用。
- **采音所有权**：wakenet feed_task 仅在 FSM 的 IDLE 态喂麦，LISTENING
  起让渡——**自唤醒免疫是结构性的**（播放期根本无人听麦），AEC
  （V-46）落地后由真打断取代。
- **放音单一通路**：TTS/beep 全经 s_pb 播放流（play_task 唯一写者）。
- **菜单**：`c`=免按键会话开关、`n`=手动注入唤醒（嘈杂环境调试口）、
  `C`=自驱回归（10 轮）；免按键会话与菜单轮/自检互斥。
- **wakenet_start 增加 on_wake 回调**：唤醒即通知 FSM（原双鸣保留）。

## 工程教训（新沉淀，按重要度）

1. **双 TLS 并发打穿内部 RAM（V-44 头号前置约束！）**：soak 首版在
   LISTENING 期用 TTS 合成提问 → ASR WS(TLS) 与 TTS HTTPS(TLS) 并发 →
   `esp-aes: Failed to allocate memory for end alignment buffer` → WS
   写崩 → 8/10 轮 ASR 失败。**V-44 流式早切必然引入 ASR WS × LLM TLS
   并发——开工前先做内部 RAM 预算与双 TLS 峰值实测**，必要时 AES 走
   软件/调 mbedtls 配置。soak 提问已改内置 PCM（零网络，'a'/'t' 已证
   过空气可转写）。
2. **convo_task 栈 16K**：轮内全程跑 ASR WS+TLS 与 LLM SSE+TLS，8K
   栈实测即栈保护故障（与主任务 16384 同规格是下限而非余量）。
3. **VAD 底噪自适应阈值必须封顶**（3600）：高噪声房间（实测底噪
   rms 2646）不封顶会算出 >11k 阈值，盖过语音电平（≈4.5k）——VAD
   永不触发，10 轮全空采。
4. **环境噪声 24 倍日波动**（同日 111 ↔ 2646）：声学唤醒检出率随
   之塌方（'W' 自检 10/10 → 1/10）。合成唤醒兜底把"轮机制验证"与
   "声学检出验证"解耦；安静环境的声学复验随真人验收走。
5. asr_open 偶发失败重试一次（WS 连接抖动）。
