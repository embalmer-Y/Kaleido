## 随行修复：缺陷 J 结案（IDLE0 饿死）

- **根因 1（主成分）**：app_main 菜单循环 getchar() 在 stdin EOF 时
  立即返回 → 80% CPU 忙旋（runtime stats 实测 main 80%、IDLE0 1%，
  TWDT 每 7s 告警，事故标签 wn_feed/soul/main 混杂皆为采样伪影）。
  修复：EOF 让出 50ms。复测 main <1%、IDLE0 82%/IDLE1 92%，告警归零。
- **根因 2（次成分）**：首启 littlefs 格式化在调用任务内连续擦写饿死
  IDLE0。修复：格式化窗口临时豁免 IDLE0 订阅，挂载完恢复。
- wn_feed 占比（10-11%）为 esp-sr 前端常态，未达饿死级，持续观察。

## 缺陷 K（结案定性升级 2026-10-29 午，已提报 esp-idf#19323）

**根因链（子智能体源码级定位 + 双解除实验闭环）**：rst:0x7=TIMG0
MWDT flashboot 保护——**硬件复位默认布防、固定 325ms**（TRM
18.2.2.4；WDTCONFIG2 复位值 26000000×12.5ns）；IDF 引导器直到
bootloader_config_wdt() 才解除（位于时钟/flash 初始化后，太晚）；
ECO7(v3.2) 全芯片冷复位模拟域 bring-up 显著变慢（esp-stub-lib
50µs→5ms→10ms 三次提交佐证）→ 首启 >325ms 撞 WDT → 二启（模拟域
热）51ms 过 → 即"双启"。SW 复位不复位模拟域故从不双启——全部观测
闭环。

**F1 修复实验（提前解除 flashboot MWDT）无效已回退**：仅解除 MWDT
→ 暴露下一层 rst:0x10 LP WDT 全芯片复位死循环（复位再冷却模拟域，
永不自愈）；MWDT+RWDT 双解除 → **首启在 entry 后无界挂起（50s+
无 banner）**。结论：双启只是症状，底里是**冷启动引导器 banner 前
无界停摆**，325ms MWDT 恰好把它自愈化。补丁已回退（板恢复双启态
=非阻断最优解）。后续：跟 #19323 官方响应；如需根治可按 E2 方案
（ets_printf 分段打点）定位停摆段。旧文案见下（历史留痕）：


现象：**仅冷上电（rst:0x1）**后，二部引导器第一行日志之前遭
`rst:0x7 (HP_SYS_HP_WDT_RESET)` 一次（第一次启动存活 ~0.4s，
含 ROM 装载），第二遍正常；**SW_CPU_RESET（panic/软复位）重启
从不双启**——冷电态专属特征。已证伪三假设：①flash 频率无关

落定不再需要）；③应用代码无关（发生在 app 之前）。嫌疑收敛：
ROM→二部引导器交接窗口的预装 WDT × 冷 MSPI/flash 初始化时长
