## 结案清单

### 1. TTS 延迟优化（截断→首音 3162→1648ms，-48%）

- 机理：t2a 每子句一次完整 TLS（~1.3s）是延迟大头；
- 三件套：暖连接跨轮存活（会话锁串行化+失败自动回退冷路径）/
  采音窗后台预热（`ks_tts_prewarm`，最小真实请求验活）/ attach 忙重试；
- soak 10/10 rc=0 实证，ttspcm-c1 从 ~2100ms 压至 200-900ms；
- **顺带完成哑音修复稳定性复验**（10 轮零静默）。
- 提交：见 git log（perf(tts) 批）。

### 2. PC 声学验证链（tools/hil/pc-acoustic/）

- 对话轮全自动（PC 播问题→ASR 一字不差→LLM/TTS 回答）；
- 唤醒：机器音色边际（模型特性非链路缺陷）——快语速 0/8、
  慢速变体 ~1/5、真人 6/6（金标准）；增益 42 下近场 >-10dB 削顶；
- 坑位沉淀：aplay 必须 -D plughw:0,0；DashScope REST TTS 已失效。

### 3. 128B 缓存行实验（结案：零增量，回退默认）

- 前提已过时：台账预测的 185KB"64B 行价"已在 esp_hosted 3.0.10
  官方 transport 修复+表达层拆除中回收（10-26 基线开机剩余 101KB
  → 今 287KB，+186KB 与预测吻合）；
- 128B 开关两态 int 池完全一致（287k）——tag RAM 不在堆口径内，
  或硬件定值；维持 64B 默认，避免无收益的非默认面。
- 屏幕管线的内存铺路由此判定：**287KB 内部余量已够**，无需更多。
